# 《雨巷猫舍》设计规格

状态：2026-07-28 接受执行。原创全年龄示例，用于驱动引擎缺口落地（内容数据库、命中区域、元进度）并验证既有系统（日程数值、回合制、图鉴、多结局）。表达全部原创；品类形状参考见 [SLG 缺口分析](../../../../docs/research/2026-07-28-imouto-rpgmv-gap-analysis.md)。

## 故事

雨季的巷尾，你盘下一间小小的猫舍。开业前夜，纸箱里传来叫声——一只湿透的奶猫。七周后是街区一年一度的"猫咪运动会"。你要经营店面、赢得街坊、把奶猫"小雨"养成能独当一面的猫——然后在结局里决定你们的关系：她留在猫舍成为招牌，夺得运动会冠军，或被真心喜欢她的富家小姐领养。

## 系统与引擎映射

| 系统      | 内容（静态，进内容数据库）                                      | 状态（动态，进模块）                    | 驱动的引擎件           |
| --------- | --------------------------------------------------------------- | --------------------------------------- | ---------------------- |
| 日程      | 时段定义（晨/午/暮/夜）、周结构                                 | 当前周/星期/时段、行动力                | 既有模块模式           |
| 活动      | **活动表**：时段限制、行动力消耗、数值效果、解锁条件            | 各数值当前值                            | **内容数据库**         |
| 猫的养成  | 成长阶段表（奶猫/幼猫/少年猫）、反应表                          | 信任、活力、技艺、成长阶段              | 内容数据库             |
| 抚摸互动  | **部位反应表**：部位×信任段→反应/数值效果                       | 每日互动余量                            | **命中区域**           |
| 运动会    | **技能表**（扑跃/佯动/卖萌）、**对手表**（3 名对手：属性+行为） | 回合内 HP/士气/回合数（战斗瞬态进状态） | 既有模块（证明回合制） |
| 图鉴/回忆 | **图鉴条目表**（成长节点/奖杯/街坊回忆）                        | 解锁集合（**跨存档**）                  | **元进度命名空间**     |
| 叙事      | 主线脚本 + 每周常客小剧情、文本目录                             | 叙事 cursor/pending/history             | 既有叙事系统           |

静态/动态边界是本设计的第一原则：左列数据 authoring 时定义、运行时只读、参与 Story 身份；右列全部走模块状态（原子提交、存档、回滚）。

## 数值系统（全部整数）

- 玩家：行动力（每日 6，晨间重置）
- 猫（小雨）：信任 0–100、活力 0–100、技艺 0–100、成长阶段（0 奶猫/1 幼猫/2 少年猫，按周推进）
- 店：声誉 0–100、金钱、整洁 0–100（每日 -10，过低影响营业收入）

## 活动表（示例行，完整表在实现中）

| id       | 时段  | 行动力 | 效果                                      | 解锁   |
| -------- | ----- | ------ | ----------------------------------------- | ------ |
| 营业     | 午/暮 | 2      | 金钱 +（10+声誉/10+整洁/20），声誉 +1     | —      |
| 打扫     | 任意  | 1      | 整洁 +25                                  | —      |
| 陪玩     | 任意  | 1      | 信任 +3，活力 -10，技艺 +1                | —      |
| 敏捷训练 | 晨/午 | 2      | 技艺 +4，活力 -20，信任 -1（阶段≥1）      | 幼猫期 |
| 采购鲜鱼 | 午    | 1      | 金钱 -15，下次陪玩信任翻倍（buff 进状态） | —      |
| 午睡陪护 | 暮    | 1      | 活力 +30，信任 +1                         | —      |

## 抚摸（命中区域）

抚摸场景：小雨立绘四个部位（头/下巴/背/尾巴）。反应由**部位反应表**决定：`(部位, 信任段位)` → 反应文本 + 信任增减 + 立绘表情。低信任摸尾巴会炸毛（信任 -3），高信任呼噜（+2）。每日互动 3 次。部位命中区域随成长阶段变化（立绘不同）。这是命中区域引擎件的验收场景：指针点击 → 命中区域 → 语义 action（`cat.pet` + 部位参数）→ 模块规则决定效果。

## 运动会（回合制）

周日暮时段自动触发（第 3/5/7 周）。3 回合技能对抗：扑跃（消耗活力，高伤害）、佯动（低伤害，下回合闪避）、卖萌（回复士气，观众加分）。对手行为模式来自对手表（激进/稳健/表演型）。技艺决定基础值，活力是资源。胜利→声誉+奖金+图鉴奖杯。失败不惩罚（鼓励再训练）。RNG 走快照（回滚防重掷已验证）。运动会开赛是 rollback barrier。

## 结局（第 7 周运动会后结算）

- 冠军线：三届奖杯全收集 → "巷口传奇"
- 招牌线：信任 ≥80 且声誉 ≥60 → "猫舍的女儿"
- 领养线：信任 <50 且富家小姐剧情线完成 → "更好的家"
- 默认线：其余 → "平凡的幸福"

## 图鉴（元进度，跨存档）

成长节点（首次开眼/第一次呼噜/学会跳跃…）、运动会奖杯 ×3、街坊回忆 ×4。解锁进 Host profile 的 Story 元进度命名空间，重开新周目保留；相册 UI 从图鉴条目表读定义、从元进度读解锁状态。

## 验收

`deno task story simulate example-cat-cafe --scenario <ending>` 四条结局线 headless 走通；抚摸/运动会/图鉴各有浏览器 spec；内容表全部经 `story check` 校验（主键/外键/textId 引用）；权威重放与回滚测试沿用 Lab 模式。
