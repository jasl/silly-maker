# Degrees of Lewdity 对照复查：今日引擎的真缺口

日期：2026-07-28。本文以当前引擎状态（R5–R7 完成、《雨巷猫舍》缺口交付后）复查 [2026-07-10 的 DoL 工程研究笔记](degrees-of-lewdity-notes.md)，回答两个问题：笔记识别的需求哪些已覆盖，哪些是今天仍然成立的缺口；以及"引擎对人类开发者友好"应该落在什么形状上。许可证边界沿用原笔记 §2（CC BY-NC-SA 参考，只提炼通用工程需求，不复制表达；生产代码与测试不读取 `references/**`）。

## 2. 今天仍成立的缺口

### A. 条件事件池（引擎级玩法原语）

DoL 品类的核心循环是"地点 × 时段 × 状态 → 候选事件筛选 → 加权随机 → 执行"，且成熟实现必须可解释（记录候选、权重、随机值、命中者）并可强制覆盖（调试直接点名事件）。我们的叙事是显式 graph（适合主线），没有池化抽取原语；猫舍这类日程游戏的"随机小事件"目前只能 Story 手写加权逻辑。

值得做成引擎件的形状（独立设计，不照搬）：

- 事件定义为**内容数据库表行**（条件列 + 权重列 + 叙事入口引用），复用解析期校验与 textId join——静态定义进表，动态冷却/已见状态进模块；
- 筛选谓词是受限的可序列化条件（对照数值/flag/时段），拒绝任意表达式执行（DoL 用宏字符串动态求值是笔记明确的反面教材）；
- 抽取走快照 RNG（`purpose` 标注），提交即事实，重放确定；
- 抽取结果携带**解释数据**（候选清单、权重、随机 draw）进 fact/诊断，DevDock 直接可视化；
- 调试强制覆盖走 debugCommand 通道（见 B），不污染正常存档。

激活条件已满足一半：猫舍的"每周常客小剧情"在设计规格里就是事件池的形状，可作第一个消费者。

### B. 可写调试面板（人类调参的运行时入口）

引擎已有完整的 **debugCommand 通道契约**：独立 schema、`validate` 预检、`executeAttempt` 与正常命令同一原子提交路径、命令日志按 `source: "debug"` 标记（重放可剥离）。但目前没有任何 Story 实现它（Lab 与猫舍都声明 `never`），DevDock 也没有消费端 UI。这条通道就是 DoL debug-menu（2170 行全局变量直改）的正确对应物——同能力、不破坏权威、不污染存档。

缺的三件（按依赖序）：

1. Story 侧参考实现：Lab 定义一组真实 debug 命令（设数值、跳推进、给资源、固定下次 RNG draw）；
2. DevDock 可写面板：从 debug schema 驱动的表单 → validate 预检反馈 → dispatch；capability 门控沿用 `debug_tools`；
3. 惯例文档：debug 命令属于开发 capability，发布构建不带。

### C. 快照结构化 diff

`stateDigest` 能判定"不同"，不能回答"哪里不同"。人类调平衡与排查回归都需要两份快照（或存档）的结构化对比：按模块状态槽逐路径 diff，输出 JSON-safe 差异清单。形状很小：Base 一个纯函数 + story CLI 一个 verb（`story diff <save-a> <save-b>`）+ DevDock 可选面板。DoL 的存档比较工具证明这是长期内容项目的刚需。

### D. simulate 数值轨迹（平衡调参的反馈回路）

`story simulate` 目前输出最终 digest 与 ok/fail。人类调数值要的是**轨迹**：每步命令后关键数值的时间序列（猫舍：信任/技艺/金钱/声誉按天）。加 `--trace <query-paths>` 输出 per-step 表格（JSON/CSV），配合内容表调参（改表 → 重跑 → 对比轨迹）就是完整的调参回路，无需任何 UI。

### E. 记录为 defer（证据不足或归属已定）

- **文本规模化组织**（DoL 是百万词级、数千文件）：我们的 textId 目录在示例量级无压力；当某个 Story 目录超过单文件可维护规模时，做"目录合并器"（多文件 → 一个 TextCatalogSet）即可，纯 authoring 工具。
- **分层立绘合成**（DoL 的 canvas 模型：body/clothes/hair 图层动态合成）：归 R8 媒体 adapter，defer 不变；我们的 appearance→renderer props 契约已能承载，缺的只是现成合成组件。
- **场景预览器/编辑器 UI**：R6.3–6.5 defer 不变。

## 3. "对人类友好"的定位

对 AI 友好与对人类友好在这个引擎里是同一件事的两面，而且大部分已经在了：

- **数据调整**：内容数据库表就是给人调的——改一行表数据，Vite HMR + dev rebootstrap 即时生效，解析期校验兜底（改错立刻报结构化错误）。这已经比 DoL 的"改全局常量 + 手工刷新"强。
- **规则调整**：规则是普通 TS 纯函数（查表 + 模块提交），改代码同样走 HMR；`story check` + focused tests 是安全网。
- **运行时调参**：上面 B（可写调试面板）补齐后，"边玩边调"闭环完成。
- **平衡验证**：上面 D（轨迹输出）补齐后，"改表 → 批量模拟 → 对比曲线"闭环完成。

换句话说：不需要为人类单独造一套工具体系；需要的是把已有通道的最后一段（debug UI、diff、trace）修通。

## 4. 建议优先级

1. **事件池原语**（§2A）——唯一的玩法能力缺口，DoL 与猫舍双重证据；设计先行，猫舍"常客小剧情"做首个消费者。
2. **debug 通道的 UI 消费端**（§2B）——人类调参的最大杠杆，引擎件已在、增量小。
3. **simulate 轨迹**（§2D）——纯 CLI 增量，调参回路立即可用。
4. **快照 diff**（§2C）——小件，随 2/3 顺手。
5. §2E 各项维持 defer，激活条件写入计划。
