## Admission 裁决（车道开启时固化；评测语义 2026-08-21 复审修订）

- **无新动词。** Host / skip / headless 只报 `TimeTickV1`。对 hold
  的 input resolve 继续 `interaction.kind_mismatch`。不复活
  `hold_abort`。
- `when` **是 branch 词汇的加法。** hold 块可选
  `when?: readonly { when: Compare; next: string }[]`——每条臂必须带
  谓词，声明序第一条命中获胜，没有隐式 else（else = 继续持有或到期
  走块上 `next`）。比较字段与该 Story 的 branch 上下文同一入院。
- **评测时机：occurrence 时间线截断，不是 commit 阶段。** 初稿的
  「折完 + 监视器后评一次」在 `{1000}×8` vs `{8000}` 下滴数与改道
  时刻分岔，违反钟合同批切不变——废弃。围栏结算按时间序步进：t=0
  评臂（读 commit 起始状态）→ 每应用一个自身 tick/`frames` 穿越评
  一次臂 → 第一条命中即截断：消耗 = 到命中瞬间的毫秒，其后穿越不
  应用，occurrence 结束，同 commit 走该臂 `next` → 时间线走完无命
  中才到期（到期与穿越同瞬间：穿越先应用，臂命中赢）。截断余量不
  预折改道目标。`settleMonitorsV1` 仍收全额上报毫秒（会话轴不截
  断）、维持折后顺序。未围栏 tick 不折 hold、不评臂；其写入在下一
  次围栏结算 t=0 浮现。
- **谓词粒度与** `activeWhen` **同纪律。** 臂读「commit 起始状态 + 本
  hold 已应用穿越」；监视器/外部命令的写入下一结算 t=0 才可见。精
  确瞬间改道只对自身 tick 效果驱动的臂承诺（两条证据路径都是），
  监视器驱动是下一结算粒度。V1 不做合并时间线。
- **入场也评。** 打开 hold 的那次 commit 按**事务内工作状态**内联
  评 `when`（提案 q2 裁决：不发明 0ms `TimeTick`；runner 在效果节
  点之后开 hold，必须看见同事务效果）。入场已真 → 立刻改道。
- **skip 不能越过截断点。** 折清是 `elapsedMs = remainingMs` 代入
  同一步进规则：途中命中 → 命中瞬间截断改道，消耗与滴数与按节奏播
  放一致；无命中才走到期 `next`。
- **base 不发明谓词 DSL。** 时间线步进助手落在 base、与
  `applyElapsedToHoldV1` 同级，收有序谓词回调（`activeWhen` 先
  例）；比较语法留在 kit，template 与实验仓 kit 同一字段。
- **不进 pending / Save。** `when` 与改道 `next` 是节点声明，与到
  期 `next` 同纪律。
- **hold 中热区（提案 q1）显式 defer。** V1 只覆盖时间/监视器/tick
  效果写入的权威状态。条中途点身体是输入轴，缺第二条 admission，
  不把 regionId 塞进 hold resolution。第一活路径是警戒抓包或深夜房
  条中途觉醒/厌恶。

## 验收

- `{500,500,500}` ≡ `{1500}` 下改道时刻、消耗毫秒、已应用穿越数、
  终态 / digest 全同；
- 入场已真 → 零流逝改道，不留下 hold pending；
- skip 折清途中命中 → 命中瞬间截断，滴数与按节奏播放一致；
- 改道目标是另一 hold 时，截断余量不预折它；
- 监视器写真的臂在下一次围栏结算 t=0 改道；
- 声明永不命中的臂 → Save / digest / 回放逐字节不变；
- 中持有 Save/load 后续走载入状态，不重演墙钟；
- 对 hold 的 input resolve 仍 `kind_mismatch`；CommandLog 无新
  resolution kind；
- Lab 两种粒度 + 实验仓一条真中止路径。

## Stop conditions

沿用 production-floor §9 与提案「停」节。本计划内特别注意：

- 新增中止动词或 Host 选臂 → 停；
- 监视器 / 热区获得路由权 → 停；
- `when` 抄进 pending / Save，或谓词读墙钟 / 指针 → 停；
- 推荐用法变成逐谓词一条命令 → 停。
