## Internal composition kernel

- `@sillymaker/composition` 提供 typed service/registry token、plugin、profile、scope、稳定
  graph identity、direct-plan compiler 与可逆 lifecycle。每个 profile 直接拥有一个 staging
  record/composite disposer；公开 API、Story 和 hot path 均不接触动态 lifecycle Context。
- Graph preflight 在 setup 前拒绝 missing/duplicate provider、duplicate registry entry、同 ID
  的不同 token object 与 dependency cycle。setup 失败逆序回滚；cleanup failure 形成诊断且继续
  sibling cleanup。
- authoritative mount 成功即永久冻结。State-backed legacy application 通过
  `activateStateApplicationV1` 保证先编译 State module direct plan，再激活 factory 并创建
  Session；State compile 失败时 factory 仍为 inactive。live profile candidate 完整 mount 后还必须
  由 consumer publisher 确认；确认期间旧 snapshot/provider 仍 current，拒绝会回滚 candidate。
  完整 mount 已安装的 live effects 会与 predecessor 共存，所以必须 staging-safe、可完整回滚且不得
  成为 publication 前的 exclusive writer；任意 publisher 的部分外部 mutation 仍由 consumer 自己
  保持或恢复。X1-X4 boot identity 不进入 Save `simulationDigest`。
- dev-only Authoring Host 是第一个真实 live composition consumer：standalone 与 embedded shell
  将 binding/scene IO/motion IO 编译为同一 direct plan，且不公开任意 live-effect 输入。publication
  保留一个 visible React root；R1 candidate 先在 inert/offscreen、document-connected staging root
  等待 layout-effect commit，connected layout failure 因而不触碰 visible predecessor，accepted
  candidate 才进入原 root 并保留兼容的 local state。同步 visible render-factory failure 可回到旧
  plan；不承诺任意 visible side effect 可逆。清理按 React consumer 在先、composition providers
  在后的顺序执行，失败转为诊断；该 Host 不持有 authoritative Session/State。connected staging
  不等于 user-visible paint 或精确 on-screen geometry，重型 geometry workspace 仍需自己的浏览器
  readiness evidence。
- X1 曾以私有 Cordis core 包裹已经由 SillyMaker 拥有的 staging/disposal；retain/remove A/B 证明它
  没有承担独立 Fiber tree、injection、isolation 或 publication 语义后，最终实现改为 package-internal
  direct lifecycle。该历史 checkpoint 只裁决 profile wrapper，不等于后续 AR1 extension-runtime
  selection；公开 exports、State/Save/replay 和维护中 Player 的 JavaScript/CSS application chunks
  当时均未改变。
- AR1 的 workspace-only `./internal/extension-runtime` 是与 profile kernel 分开的 private Direct
  runtime：neutral factory 可 direct mount 或交给 activation controller；required domain/local
  binding 在 mount 前 admission，optional sibling failure/retry 隔离，nested child/reversible effect、
  provider loss/recovery、late-result fence、predecessor retention 与幂等 async cleanup 由同一
  conformance contract 覆盖。historical Direct/Cordis 17-case A/B 后只保留 Direct，Cordis
  adapter/vendor/dependency 已删除；domain、Story 和 public contracts 不出现 Cordis/Context。
- 外部 X6.2/X6.3 workload 把 concrete registries 限制在 Session 前的 cold environment，并让
  compiler/runner 只保留冻结 script、一个 runtime node index、choice maps 与 direct gate/effect
  functions。Simulation/semantic hot consumers 不查询 registry 或 lifecycle Context；兼容名称仍是
  同一个 singleton runtime 的 exact aliases。外部源码和内容不属于引擎 feature 或 fixture。

## Experimental neutral State Runtime

- `@sillymaker/state` root 提供 `StateRuntimeV1`、`StateSessionV1`、
  `StateSnapshotV1`、`StateRuntimeDefinitionV1` 与相关 command/result 类型，公开声明不暴露
  lifecycle Context 或 legacy Game 命名。`createStateRuntimeV1` 通过 Base
  `createGameSessionV1` 只创建一次底层 composition，并把其 exact Session 作为唯一权威返回；
  facade 不代理、不展开，也不复制 State、digest、status、queue 或 CommandLog。
- `@sillymaker/state/legacy` 提供迁移期 adapter，可同时取得同一个 neutral runtime、exact
  `GameSessionCompositionV1` 和 exact `GameSessionRuntimeControlV1`。它用于行为/类型等价验证，
  不是新的 Story-facing production API。同一子入口的
  `createLegacyGameplayModuleBindingsV1` 通过 Base 公开 constructor 重新 admission 完整 binding、显式
  复制全部 stateful/stateless 字段并附着 aggregate command Schema，避免迁移 Story 依赖
  中立 descriptor 未承诺的 Base 字段或 `as unknown`。
- `createStateAuthoringKitV1` 提供中立 `StateModule`、capability、`StateTransaction` 与
  `StateWorkflow`，内部直接复用一个 Base authoring kit/transaction runner。原创四模块 pilot
  验证一次提交与完整回滚；没有第二份 event journal、candidate State、RNG 或 commit path。
  module 暴露 admission 时冻结的 `contractRevision`，冷路径私有 carrier 只引用同一个 Base module，
  spread/prototype alias 会 fail-fast。V1 initializer 明确不读取 bootstrap；module 以 domain-event
  kind 声明纯 reducer，workflow 以 `eventSchema` admission 事件。transaction 只读 command-start
  State、无 read-your-writes，拒绝必须发生在 emit 前；module State slot 必须彼此正交，exact 或
  parent/child overlap 在 cold composition fail-fast。cold direct plan 把 event kind 映射到 UTF-16
  module ID 有序 subscriber；hot fold 保持 emission order，只访问实际 subscriber，同一 owner 的重复
  event 累积为一个 proposal。每个 touched owner 只 validation 一次，所有 touched slot 经一次稀疏
  aggregate State materialization 写回；无订阅事件保留为 journal-only evidence。reject/fault 保持
  Snapshot 与 committed RNG 不变。module-local invariants 尚无已定义执行点，当前只支持 workflow
  aggregate `validateCandidate`。
- 当前 Snapshot/State 物理格式、whole-Snapshot digest、Save、Persistence、migration、
  CommandLog 与 replay 仍由 `@sillymaker/base` 的既有实现权威拥有。尚无 State Format V2 或
  production Story 迁移。
- 主仓提供一个 16-module neutral Composition/State benchmark：3x3 exact-Save/touched-owner matrix
  先证明 256 commits、200-entry retention、authoritative replay 与 isolated import/export，再把
  steady command、cold activation 和五个 process-isolated GC cells 分开采样。它不添加 production
  instrumentation 或第二 authority；绝对 timing/heap 只作本机 trend，不进入普通 CI hard gate。

## Story authoring and resolution

- Typed `GamePackage`, `GameSimulation`, and `GameplayModule` definitions.
- A dedicated `@sillymaker/base/authoring` entry with `createRuntimeSchemaV1` (canonical-JSON output, deep-freeze, structured failures) and `fromStandardSchemaV1`, the official Zod adapter accepting any Standard Schema V1 implementation without leaking library types.
- `createGameAuthoringKitV1`: typed capability tokens, `requires`/`provides` with provider factories that build narrow read-only ports from the module's own State slice, disjoint State-slot ownership (exact and parent/child overlap fail at cold composition), a validated capability availability DAG plus an independent `initializesAfter` lifecycle DAG, stateful/stateless module helpers, and composition into ordinary low-level module bindings. The low-level `defineGameplayModule`/`defineGameSimulation` API remains the escape hatch; one composition owns one resolved module graph.
- A composition-level transaction runner (`createTransactionRunner`) for cross-module atomic commands under the domain-event model (parallel-monitors lane M1, 2026-08-20; M2 direct hot plan, 2026-08-24): `read(token)` observes the command-start Snapshot, the handler performs every gameplay refusal via `reject(...)` before emitting, and `emit(event)` journals a decided outcome after validating it once against the Story `eventSchema` — `emit` itself never rejects. Cold composition maps event kinds directly to UTF-16 module-ID-ordered subscribers. After `complete()`, the engine folds events in emission order without scanning unrelated modules, carries one running proposal per touched owner, validates each owner once, and materializes all touched slots through one sparse aggregate-State copy before aggregate validation. Events with no subscribed reducer are journal-only broadcast evidence. The engine owns schema/invariant validation, journal collection, commit/reject/fault envelopes, and RNG/sequence rollback; Snapshot digest/freeze, CommandLog, Save, and replay remain unchanged.
- Engine-owned Strict Canonical Data admission at every public Session/Simulation/CommandLog command ingress and authoritative replay: one descriptor-safe command traversal rejects symbol-keyed members, extra own array properties, custom array prototypes, and represented accessors while generating the unchanged canonical bytes plus a new path-local ordinary-data projection. Only that projection is frozen and delivered to the executor/log/replay driver; admission neither retains nor freezes the upstream normalized identity (schema helpers may already have frozen their own output), shared aliases expand per canonical path, and ingress-attached Proxy/private/WeakMap state cannot cross the boundary. One exact-projection operation receipt prevents duplicate traversal. A malformed command fails before queue/status publication, RNG, Snapshot digest/freeze, continuity, or driver construction; Story schema/domain failures keep their existing result contracts, while canonical violations use root-exported `CanonicalJsonError` with stable `code` and JSON-Pointer `path`. Authoritative replay captures every source/command slot once, runtime-validates `game | debug`, prepares the projection vector, and freezes none until every entry passes; even a valid `null` projection is submitted without rereading its slot. Public `canonicalJsonBytes`, digest, Save, Debug Bundle, and valid CommandLog/replay bytes remain unchanged; best-effort inspection is unchanged. Direct generic CommandLog extras are conditionally projected/frozen as independent metadata while retaining public key order; enumerable collisions with engine-owned entry fields reject synchronously, and the standard Session path has no metadata traversal.
- Engine-owned finalized-evidence admission for Session, independent CommandLog, authoritative replay, Debug validation failures, and structurally attempt-shaped direct Simulation results: descriptor-only outer capture preserves getter-zero behavior and Standard Core's zero-RNG precedence; every evidence collection captures one own array `length` data descriptor and validates indices against that fixed length, so Proxy virtual length cannot alter the vector. Declared domain-event/rejection/debug-error schemas normalize each item before one Snapshot-free Strict Canonical Data projection traversal and freeze. The admitted projection flows into an engine-rebuilt attempt, and an exact admitted-attempt package-internal one-shot handoff carries it to CommandLog; admission itself neither retains nor freezes upstream normalized evidence, while a schema's own freeze contract remains in force and result/pre-attempt Snapshots deliberately retain authoritative identity. No public evidence hook, receipt, fault schema, result branch, or `GameSimulation` revision was added. Failure occurs before candidate Snapshot integrity/freeze/digest, log continuity, install, or publication. Session invokes its existing unexpected-fault normalizer once; only a valid same-Snapshot canonical fault fallback is logged and pauses the Session, while an invalid fallback rejects without recursive normalization or authoritative mutation. Opaque non-attempt `GameSimulationV1` generic results remain unchanged, and valid Snapshot/digest/Save/replay/DebugBundle bytes retain their existing formats.
- The bounded Strict JSON parser classifies number tokens from exact decimal coefficient/scale/exponent data before final conversion. Mathematical safe integers keep accepting alternate spellings such as `1.0`, `1e0`, and trailing-zero cancellation; rounded fractions reject as `number.not_integer`, true negative-zero spellings as `number.negative_zero`, and exact out-of-range integers (including non-finite conversion outcomes) as `number.unsafe_integer`. The enclosing byte limit is the resource bound, no Decimal/BigInt runtime or exponent-sized allocation is introduced, and decoder failure exposes no partial value. Valid Save metadata vectors, Save/DebugBundle normalization, canonical bytes, and digests remain unchanged.
- Standard Core treats Story-owned `createBootstrapInput` as a Host-ingress adapter. Before reading the RNG seed or invoking root/module initializers, one package-internal Strict Canonical Data traversal builds a path-local ordinary projection and one recursive freeze seals that engine-owned handoff. The adapter raw value remains caller-owned and unfrozen; shared aliases expand per path, cycles reject, and Proxy/private/WeakMap identity state cannot enter authoritative initialization. Construction, queued restart, and the captured extension `createInitialSnapshot` helper share the same stage order and failure precedence. The seed is descriptor-read and parsed once from the admitted projection, then the same frozen identity reaches the resolved root and each stateful module initializer in tuple order. Canonical, freeze, seed, Story/schema, and Snapshot failures retain their existing public channels and cannot install a partial Session, replay base, or persistence anchor. This adds no public bootstrap schema, receipt, or hook and preserves valid initial Snapshot, digest, Save, and replay bytes.

- The Base application composer (`@sillymaker/base/runtime`): `defineCoreGameApplicationV1` declares a Host-neutral core application (GamePackage entry, semantic adapter, validators, diagnostics extensions — no React, no Host handle); `resolveCoreGameApplicationV1` produces an immutable reusable resolved definition with structured failure reporting; `createCoreGameApplicationInstanceV1` creates a disposable instance that owns the Session, semantic port, persistence lease, diagnostics buffer, and lifecycle (`restart`). Failed construction and idempotent disposal leave no active owner or listener. Each instance maintains an instance-local presentation anchor/epoch that advances when the authoritative replay base is replaced (load/import/restart/debug anchor, with origin labels) and never enters SemanticPublication, semantic revisions, or Agent transcripts; `bindToCurrentEpoch` guards stale presentation callbacks structurally. `GameSession` keeps its current Snapshot digest as private derived evidence: committed Snapshots are frozen before one post-state digest, rejected/faulted attempts reuse the current digest, and every replay-base replacement refreshes Snapshot, CommandLog anchor, and digest together. The hot Session path retains object-identity and digest-chain checks without re-traversal, while the public low-level `createCommandLogV1` keeps full digest self-audit. Persistence can reuse that derived evidence only for the exact installed Snapshot under the exact Session runtime-control identity; custom/wrapped controls, cloned Snapshots, schema-normalized copies, and physical readback keep independent digest validation. The built-in Save repository also binds a successful exact write attempt to one private one-shot expected-byte receipt, so write verification can compare the physical readback without re-encoding the same current envelope; custom/decorated repositories retain the independent expected-encoding fallback, and lease, schema, digest, revision, and raw-byte readback checks remain in force. Built-in Save encoding performs canonical serialization and Strict depth/node/collection/string/dangerous-key checks in the same internal traversal; decoding untrusted bytes still uses the complete Strict parser before schema and digest validation. Autosave is an injectable policy (`every_commit` default, or `debounced` with `delayMs`, optional `checkpointEveryCommands`, an injectable scheduler for deterministic tests, and `flushAutoSave` for lifecycle hosts). Debounced admission requires `delayMs` to be a non-negative safe integer other than `-0`, and an optional checkpoint to be a positive safe integer; invalid policies fail before Session creation, persistence lease acquisition, timer access, or Host writes. A flush registers the exact current authoritative Snapshot at the Session queue front and succeeds only for that candidate's verified `auto.current` receipt. A same-sequence manual save cannot mask failure, initial and replacement Snapshots are eligible without a new command, duplicate exact captures reuse in-flight or already-verified identity, failed current attempts remain retryable, and replay-base replacement supersedes old-epoch receipts. Explicit slot saves remain available under any policy. Low-level constructors (`createGameSessionV1`, `createPersistenceServiceV1`, `createSemanticGamePortV1`) stay public as escape hatches.
- Persistence safepoints and in-flight spans V1 ([parallel-monitors lane](proposals/parallel-monitors.md) M3, 2026-08-20): an application may declare `persistenceSafepoint: { classify, maxInFlightCommits }` on `defineCoreGameApplicationV1` — `classify` is a deterministic read of committed authoritative state returning `safepoint` | `in_flight` (derive it from existing vocabulary: the Engine Lab classifies a pending `presentation_barrier` as in-flight), and `maxInFlightCommits` (1..256) is the admission-enforced span bound (`parsePersistenceSafepointPolicyV1`; an unbounded or malformed declaration fails resolution with `persistence_safepoint.invalid` before any Session or persistence owner exists). While a span is open the orchestrator defers autosave — under `every_commit` an in-flight commit never becomes a candidate; under `debounced` the last safepoint candidate and any timer already running for it stay in place — and `flushAutoSave` falls back to the most recent safepoint Snapshot of the current anchor era (with none, the flush writes nothing and the stored pre-span record remains the crash-recovery target). Player-slot saves inside a span reject with the `in_flight` code (the default Save overlay renders the Story's `rejected.in_flight` label); loads stay available, and a load/import/restart anchor replacement resets span tracking so a pre-replacement safepoint Snapshot can never write into the new era. The bound keeps spans honest: exceeding it forfeits the inhibit with one `persistence.safepoint_span_exceeded` diagnostic until the next safepoint commit, and a throwing or malformed classifier reports `persistence.safepoint_classify_failed` and fails open as a safepoint — a malfunctioning declaration can never starve the Save. The classification never enters authoritative state, Saves, digests, or replay: every commit remains complete, valid, and replayable — a span only expresses a re-entry preference. It is orthogonal to the UI-level `saveGuard` (which disables the manual-save control with a stated reason over the live publication): the guard is presentation intent, the safepoint policy is orchestration that also covers autosave and flush. The barrier's `loadRecovery` vocabulary stays authoritative for Saves that do capture a pending barrier (bound forfeits, legacy records, imports) — the Engine Lab's default-UI suite stages such a legacy record and proves it still settles on load.

- The authoritative hold clock (accepted 2026-08-19, [proposal](proposals/authoritative-hold-clock.md); time verb unified 2026-08-20 by the [parallel-monitors lane](proposals/parallel-monitors.md) M0): `hold` holds the screen between two lines for an authoritative duration — `totalMs`/`remainingMs` as positive integer milliseconds plus the author's `skippable` flag (original 60fps frame counts convert at Story compile time). Elapsed time reaches the session through the single session-level time verb `TimeTickV1` (`parseTimeTickV1`/`evaluateTimeTickV1`; story facade `parseTimeTick`/`evaluateTimeTick`): a tick carries `elapsedMs` plus an optional `expectedHoldOccurrenceId` hold fence — fenced ticks fold the pending hold and reject as stale once the occurrence expires, unfenced ticks are accepted unconditionally and never fold a hold — they settle the session-global time consumers (declared authoritative monitors; a hold-free, monitor-free Story commits them as observable no-ops). Holds are pure time-settlement boundaries: every input resolution against a hold rejects with `interaction.kind_mismatch`, and the retired `hold_tick` resolution kind no longer parses. `applyElapsedToHoldV1` (facade `applyElapsedToHold`) is the shared runner arithmetic: it consumes `min(elapsedMs, remainingMs)` (overshoot clamps instead of rejecting), keeps the same boundary occurrence while a remainder is left, and expires into the node's successor on the tick that reaches zero (no separate `hold_expire`). The terminal state depends only on the millisecond sum, never on Host batch splits; wall clocks stay out of State, Saves, digests, and replay. The Story's narrative surface binds the `dispatchTime` port next to `dispatchResolution` (nullable for hold-free stories); the Narrative Host's hold-expiry controller settles expiry as one fenced tick commit, and a skippable hold's player input folds the remainder the same way via the retained `narrative.resume` physical action id. The authoring surface: the starter template's interaction-document kit compiles a `hold` block (positive integer `durationMs`, optional `skippable`, optional inline `ops` that become a preceding stage node so the held picture is committed stage state rather than a flash), the template runner settles ticks through `applyElapsedToHold` and distinguishes holding from advancing, and the Studio Flow graph projects `hold` nodes. The template opening consumes one live hold, and a mid-hold Save/load restores the last committed remainder. Tick machinery: a hold may declare an optional `tickQuantumMs`, the Narrative Host accumulates presentation-clock elapse and commits partial ticks per quantum (without a quantum it still commits only fold/expiry), narrative reconciliation accepts a same-occurrence hold frame whose only change is a decreased `remainingMs` (anything else still faults), and `countThresholdCrossingsV1` (story facade `countThresholdCrossings`) is the shared batch-invariant threshold-crossing arithmetic — a Story settles per-interval tick effects and mid-hold frame swaps inside the same commit by counting thresholds crossed in `(before, after]`, so command batch splits can never change outcomes. Engine Lab's `cal-hold` declares a tick effect as the first consumer; an external workbench Story's timed-drip path (an authoritative +1 every 5 s plus a threshold frame swap and a same-commit meter read) is the second.
- Declared hold reroute arms (hold-when, accepted and delivered 2026-08-21, [proposal](proposals/hold-when.md)): a `hold` node may declare ordered `when` arms — a branch-vocabulary predicate plus a reroute target; every arm carries a predicate (no implicit else — no match means keep holding or expire into the node's `next`), and the first declared match wins. Arms are occurrence-timeline cuts, never an end-of-commit phase: `settleHoldTimelineV1` (story facade `settleHoldTimeline`, the shared stepping helper beside `applyElapsedToHoldV1`) walks a fenced settlement in time order — arms evaluate at t=0 against command-start state and again after each of the hold's own tick/frame crossings, and the first match truncates the hold at that instant (consumed milliseconds stop at the cut, later crossings never apply, the discarded remainder is never pre-folded into the reroute target) with the same commit walking the arm's target. The opening commit also evaluates arms against in-transaction working state, so an already-true arm reroutes without ever spending a hold occurrence, and a skippable fold feeds `remainingMs` through the same stepping so skip cannot fast-forward past the catch instant. Batch invariance holds (`{500,500,500}` ≡ `{1500}` in cut instant, consumed milliseconds, applied crossings, and digest). Predicate granularity follows the `activeWhen` discipline: same-instant reroutes are promised only for state written by the hold's own tick effects; monitor or external-command writes surface at the next fenced settlement's t=0. Input stays out — resolutions against a hold still reject `interaction.kind_mismatch`, no new verbs or resolution kinds exist, and arms/targets are node declarations that never enter pending state, Saves, or digests. Consumers: the starter template kit compiles `when` arms (flag conditions) with a starter-script hurry demo; Engine Lab locks both granularities (a tick-driven vigil cut at the exact crossing; a monitor-driven stakeout cut at next settlement's t=0) plus Flow reroute edges; the external experiment repo's night-room touch gauges cut mid-bar on the watcher exception (wake/disgust/timeout) as the first live abort path.
- Mid-hold input writes ([mid-hold-input proposal](proposals/mid-hold-input.md), accepted 2026-08-22): the input axis of hold `when`, delivered as a Story-side composition of already-shipped contracts — **zero new engine primitives**. - Ambient loop motion (ambient-loop-motion proposal, accepted 2026-08-15): presence-bound looping motions for settled stage entries — breathing/blinking character idles and outdoor environment loops (drifting cloud or mist bands, window rain) are the same primitive. ## Content database

- Story-defined static data tables: `defineContentTableV1` validates a table at definition (table-id pattern, per-row RuntimeSchema parsing — typically zod via `fromStandardSchemaV1` — unique non-empty string primary keys, row limits); `createContentDatabaseV1` validates cross-table references at construction and exposes typed read-only views: `byId` (KV), `findMany`/`findFirst` with `where` conditions (eq/ne/in, numeric comparisons, array membership) and ordering, plus `collectTextIds` for text-catalog joins. ## Gameplay primitives

- Event pool: `parseEventConditionV1` validates restricted serializable condition trees (number/flag/label leaves, all/any/not composition, depth and branch bounds). Evaluation/draw captures each own enumerable numeric-context value once into an engine-owned projection, admits the complete projection as safe integers, and rejects fractional, non-finite, unsafe, or negative-zero values; inherited numeric properties are missing rather than an admission bypass. Draw also captures each candidate id/weight/condition once, then eligibility, accumulation, force, explanation, and selection consume only that projection. Eligible weights accumulate with a pre-add safe-integer overflow check across the complete authoring-order vector, including forced selection; invalid context/overflow fails before RNG or explanation. Valid draws use one purpose-tagged transactional-RNG roll with JSON-safe explanation data (considered, eligible weights, roll, winner), while debug force preserves eligibility and spends no draw. ## Persistence and compatibility

- Game-shell native-behavior reset (`@sillymaker/ui` `installNativeBehaviorResetV1`, installed by the web composer by default; a Story opts out with `input: { nativeBehavior: false }` or tunes it via the same key of the unified `input` declaration on the web UI definition): a "reset CSS" for browser input defaults — suppresses the context menu, text selection, touch callouts, image drag, and hover-cursor changes document-wide so a Player feels like a game shell. Only editable controls (`input`/`textarea`/`select`/contenteditable) keep native selection, menus, and the text cursor automatically (their menu is the copy/paste surface); buttons and other interactive controls are application-owned — the browser menu stays suppressed there and right-click routes through the Input Router (`data-secondary-action` on controls, stage `secondary` mapping). Any subtree opts back in with `data-native-menu` (browser menu) / `data-native-text` (selection + text cursor); links keep the pointer cursor. Inside an opted-in subtree the boundary stays control-aware: non-editable control faces (buttons, links, summaries, options) remain unselectable — a debug panel with `data-native-text` gets a copyable status summary while its button labels stay controls. Document-scoped on purpose because Story overlays portal to `document.body`; disposal removes every installed piece. The reset is a presentation floor, not a semantic owner: its Window-bubble listener runs after the document-level pointer adapter, exposes no raw context-menu callback, and yields when that adapter has claimed the event, and the stage CSS keeps its own selection/zoom/scroll-chaining suppression for the shell subtree.
- Desktop-channel persistence preview: `createHttpHostRecordStoreV1` is the browser-side adapter for the trusted local records endpoint. The Deno save server and packaged shell validate same-origin JSON requests, bounded bodies, namespaces, revisions, paths, and stored records; their current JSON-file backend provides optimistic revisions, a serialized in-process queue, and atomic **per-record** replacement. It does not yet prove crash-atomic multi-record commits, cross-process CAS, or a portable collision-free filename mapping for arbitrary record keys, so it remains a preview/reference backend pending the [desktop durability plan](plans/2026-07-30-desktop-persistence-durability.md). `startWebGameApplicationV1` selects the HTTP adapter when the page runs with `?records=local` or the shell injects `__SILLYMAKER_RECORDS__`.
- Usable Desktop packaging preview: `deno task build:desktop` (where the application declares it; `deno task story desktop <app>` from the root) stages a thin shell shipped inside `@sillymaker/tooling`, serves the built Player from embedded `dist/`, injects the local-records signal plus one per-launch capability, and owns a save directory under the platform user-data location. All shell traffic is admitted only for the exact runtime-selected loopback origin; private records/download requests also require the captured capability and reject cross-site or mismatched-Origin traffic. Launch-specific HTML is uncached and cannot be framed by another page. The download bridge has bounded concurrency and body deadlines, atomically publishes no-clobber files, and removes cancelled partials. The shell adopts Deno Desktop's startup window; native close synchronously fences gameplay ingress, starts a renderer-side autosave flush, and reads only that close request's JSON receipt. A verified receipt first cancels only non-authoritative downloads still receiving bodies, then allows HTTP admission to stop, active record commits to drain, and the process to exit; a missing or failed receipt keeps the window, server, and download ingress alive, with no heartbeat, watchdog, or timeout force-exit. The app config's desktop name, reverse-DNS identifier, and optional icon drive `deno desktop`; the default output is a host-platform preview, and explicit supported `--target <triple>` flags add cross-compiled packages per OS (macOS `.app`, Windows `.msi` installer, Linux `.AppImage`) with optional payload compression. Signing/notarization, per-platform launch smokes, and durable-store promotion are not yet live capabilities.

- Quick Save, automatic Save, and numbered manual Save slots (`manual.1`..`manual.N`) through a Host persistence facade; the manual slot count is Story-configurable (`manualSaveSlotCount` on the core application definition, engine default 8, range 0–99; zero disables numbered manual slots). (Pre-release clean break: records stored under the retired bare `manual` slot key are no longer enumerated.)
- Save annotations: an optional `summarizeSave` hook on the core application definition captures application display lines whenever it creates a fresh record (auto, quick, manual, or current-state export); exporting an existing stored slot preserves that record's bytes. `annotateSave(slot, note)` on the player persistence port edits a bounded player note in place (empty string clears; snapshot, capture time, and summary stay untouched; auto slots stay read-only). `SaveSlotSummaryV1.annotation` exposes both to Story-owned/custom slot UI; limits live in `saveAnnotationLimitsV1` (8 lines × 120 code points, notes ≤ 64 code points). Gameplay surfaces also disable text selection, image dragging, the iOS long-press callout, double-tap zoom, and scroll chaining wholesale. Native form controls (text fields, selects, textareas, checkboxes, ranges) take the theme automatically. Window exclusivity is structural — one system-dialog slot, one workspace primary (`openPrimary` replaces) plus a detail stack. A WindowManager (minimize/maximize/taskbar/z-order persistence) stays out of the engine. Letterboxed CSS-pixel floaters drag with `useClampedElementDragV1`; scaled MDI drag stays Story-side. Recipes live in design/window-model.md.
- Window chrome: `PanelV1` is the shared in-game window frame (visible title bar, optional header actions, close control, keyboard-focusable scrollable body). Close is a labelled button by default (`closeControl: "label"`) or an icon whose accessible name is `closeLabel` (`closeControl: "icon"`). `OverlayHostV1` wraps every workspace overlay in it, so gameplay windows (album, shop, inventory…) get consistent chrome for free, with content-first initial focus (the close button never steals it). Floating debug windows (`DevDockV1`) reuse the same chrome with the icon close and title-bar drag (`headerProps` + `useClampedElementDragV1`); they are not OverlayHost sessions. Styling comes exclusively from the published `--silly-*` theme tokens (colors, spacing, radii, control/target sizes, stacking). The default theme is professional-neutral dark (no brand hue) with compact control chrome: buttons and system bands size from `--silly-control-min-size` (2rem), while `--silly-target-min-size` (44px) remains the touch-target floor token for stage hit areas.
- Immutable presentation projection that combines semantic output with local presentation state without becoming gameplay authority.

- Stage hit regions: `StageContentResolutionV1.hitRegions` lets the content catalog resolve activatable regions per contentId + appearance (regions can move as a character grows); projection validates and bounds them (up to 64 regions per entry), and `SemanticStageHostV1` renders them as focusable transparent buttons only when the Story passes `onHitRegionActivate`, so pointer, touch, and keyboard reach the same semantic invocation path. Regions are presentation data and never carry gameplay authority; availability stays with semantic actions and module rules. The empty scene-interaction layer no longer mounts, so it cannot swallow stage pointer input.
- Shaped hit regions and hover reveal (shaped-hit-regions, accepted 2026-08-21): a region may refine its bounding box with `polygonPoints` (3–64 integer vertices in the same anchor space, inside the box, non-zero shoelace area — shared judgment `hitRegionPolygonValidV1`); the host clips the region button with CSS `clip-path`, so pointer hits follow the shape natively (browsers exclude clipped pixels from hit testing — the runtime never reads image pixels) while keyboard activation keeps the bounding box, whose focus indicator is a sibling element because `clip-path` would clip the button's own outline. An optional `hoverAssetId` names a same-frame highlight: while the pointer rests inside the shape or the region button holds keyboard focus, the host aligns that asset to the entry's declared geometry box as a presentation overlay (silhouette flashes are authored same-frame as the base art); it joins `requiredAssetIds` for preloading and resolves through the optional `assets` port (`AssetUrlRegistryV1`) on `SemanticStageV1`/`SemanticStageTargetHostV1` — no registry or no geometry simply renders no reveal, never changing activation semantics (the reveal is a pointer-hover/keyboard-focus affordance; touch taps activate directly without a hover phase). Invalid refinements degrade instead of dying: a bad polygon drops to the rectangle (`stage.hit_region_polygon_invalid`), a bad hover id is discarded (`stage.hit_region_hover_invalid`). Catalog order is both DOM/focus order and bottom-to-top paint order inside one entry, so a later region wins pointer overlap; the Authoring Scene facet projection exposes the corresponding reverse, topmost-first pick sequence explicitly rather than asking future Inspector code to rediscover it from DOM. Hover state never enters authoritative State, Saves, or the CommandLog. Consumers: the Engine Lab crate's octagonal collection port (regions Document + hover glow + activation dispatching the ordinary collect invocation) and the external experiment repo's three-pose night-bed body zones (rect-intersect-silhouette polygon refinements of the original all-opaque rectangle judgment art); the Cat Cafe petting zones stay plain rectangles on the base hit-region contract, untouched by this lane.
- Regions documents and tooling: `sillymaker.regions` is the third authoring document family (`*.regions.json`, `parseRegionsDocumentV1` strict admission in `@sillymaker/base` — unique regionIds, vertex/box rules identical to projection so an admitted file cannot degrade at runtime). Story code imports the JSON, parses it once, and hands `document.regions` to `resolveContent` — the same locality as motion documents binding cues. The Project Authoring Index discovers the family (list + named skips), `story check` lints it (`regions.document_json_invalid` / `document_invalid` / `id_duplicate` / `id_filename_mismatch`; duplicate regionIds inside one file already fail admission), and the dev server exposes list/read/write/create CAS ports (`/__sillymaker/dev-sources/regions-document[s]`, isomorphic to the motion port). Studio gains a Regions workspace: pick a regions file, pick an entry of the compiled scene as the live backdrop, and edit against the real host rendering — the actual clip-path shapes and hover reveals are the preview; drag the bounding box, scale from the corner, move/insert/delete vertices, convert rectangle⇄polygon, all through pure `regions-edit.ts` commands on the shared authoring document session (same CAS/undo/dirty-navigation discipline; saving re-runs admission and graduates `authoring.status` to `human_tuned`). For legacy bitmap judgment art, the `story regions trace <image.png> --out <file.regions.json>` devtool converts an alpha silhouette into an editable single-region document (strict minimal PNG alpha decoder for untrusted input; threshold → largest 4-connected component → marching-squares boundary walk → closed-ring Douglas–Peucker into the vertex budget with the smallest feasible epsilon; vertices stay a subset of exact boundary corners) — pixel semantics exist only at import time, never in the runtime contract.
- Chrome-layout documents and tooling (authorable-chrome-layout, accepted 2026-08-22): `sillymaker.chrome-layout` is the fourth authoring document family (`*.chrome-layout.json`, `parseChromeLayoutDocumentV1` strict admission in `@sillymaker/base`) carrying the hand-tuned placement geometry of one chrome surface in logical canvas space — `boxes` (placed rectangles: negative positions are legal, sizes ≥ 1), `anchors` (position-only points for self-sizing elements), and `offsets` (named integer scalars), ≤ 256 entries total, exact keys, safe integers, prototype-polluting entry names rejected. Story code imports the JSON, parses it once, and reads named entries as frozen typed data; behavior booleans, occupancy gates, and intent legality stay in Story code, and layout documents never touch State, Saves, digests, or replay. The Project Authoring Index discovers the family (`chromeLayouts` + named skips), `story check` lints it (`chrome_layout.document_json_invalid` / `document_invalid` / `id_duplicate` / `id_filename_mismatch`), and the dev server exposes list/read/write/create CAS ports (`/__sillymaker/dev-sources/chrome-layout[s]`, isomorphic to the motion and regions ports: sha256 digest CAS, 409 on stale digests, atomic tmp+rename, id↔filename-stem stability). Studio gains a Chrome workspace (界面布局): a document list with a create form (layoutId prefix inferred from existing layouts), a logical-canvas preview where boxes drag and corner-scale, anchors drag as points, and offsets edit as numeric rows, all through pure `chrome-edit.ts` commands on the shared authoring document session (same CAS/undo/dirty-confirm discipline as Regions; saving graduates `authoring.status` to `human_tuned`). The preview renders the Story's real chrome when the binding declares an optional `chrome` fixture list (`StudioChromeFixtureV1`: `layoutId` + `render(draft)` — the real component with frozen sample data and a no-op semantic port, geometry read live from the draft, crash-isolated behind an error boundary with a wireframe fallback); documents without a fixture render as an editable wireframe (box outlines + anchor dots), so nothing requires a fixture to be authorable. The starter template is the first consumer: `template/src/chrome/hud.chrome-layout.json` positions the HUD status strip, `TemplateHudV1` reads the same document at runtime, and the binding's fixture renders that real HUD inside the workspace — dragging the box and saving moves the game's HUD with zero code edits.
- Stage entry opacity: `StagePlacementV1.opacityPermille` (integer 0–1000) is a required placement field — the authoritative settled opacity of each stage entry, entering Snapshots and Saves like every other placement channel (semantic stage contract revision 3). Transition fades and timeline overlay opacity compose multiplicatively on top as presentation and never persist.
- Dev-sources origin guard: every `/__sillymaker/dev-sources/*` endpoint (open-in-editor plus the scene/motion/regions/chrome-layout CAS ports) sits behind one same-origin gate registered ahead of the port middlewares — a browser request whose `Sec-Fetch-Site` is neither `same-origin` nor `none` is rejected 403 whole, so an arbitrary web page open in the developer's browser cannot pop the editor or write schema-valid documents into the project tree. Headerless callers (curl, scripts, tests) pass, and the endpoints continue to exist only under `vite dev`.

## Web Host and application delivery

- Explicit Story-to-application composition and React mounting.
- Injectable autosave/checkpoint policy with a debounced browser default (`defaultWebAutosavePolicyV1`: quiet-period flush plus an every-N-commands checkpoint backstop), so committed Snapshots stay saveable at any time but long dialogues never write IndexedDB per line; the pagehide teardown flushes any pending capture before releasing the lease.
- Multi-instance lease coordination (`createWebInstanceLeaseCoordinatorV1`, composed automatically by the web start path): one unique lease owner per started tab/window/process, a declared `instancePolicy` applied against a live holder (`take_over` seizes at boot and reports `lost` when seized back; `read_only` never contends; `wait` runs read-only until the holder exits, then claims with CAS semantics so it never steals from a faster contender; `unrestricted` re-seizes on every loss — explicit last-writer-wins), a free lease always claimed regardless of policy, and an observable role port (`state.getCurrent`/`subscribe`, `refresh`, manual `takeOver`) handed to `application.ui()` and the started handle, together with `clearAllSaves` (Core wipe: drain pending Auto Save, then every slot) so a Story debug dock never loops `savePort.clear`. Role freshness combines a poll with a same-origin BroadcastChannel nudge on seizures; fencing tokens still reject every write from a seized instance, so no policy can corrupt a newer save.
- `createWebAudioHostV1`: the browser Audio Host — verifies fetched bytes against the declared length and sha256 before decode (mismatches degrade to silence with an integrity diagnostic), caches decoded buffers while letting failed loads open a new cycle on later demand, unlocks the AudioContext on the first user gesture (queued continuous channels apply on unlock; locked one-shots are dropped with a diagnostic, never replayed), applies permille gains with linear fades, and suspends/resumes/closes with page lifecycle. Autoplay denial and missing or undecodable media never block gameplay.
- Neutral Application Host capabilities for IndexedDB records, files, metadata
  clock, and logging; the Game Domain admits browser crypto entropy separately.
  Image loading and routing remain explicit Web composition concerns rather
  than universal Host capabilities.
- Hash routing and query-driven development capabilities.
- Loader recovery when a Hotfix cannot be admitted.
- Vite development and static Player builds.
- Optional local handoff-Artifact preparation with legal files and a technical
  integrity manifest; hosted Players may deploy `dist-web/` directly and expose
  applicable licenses through an in-product page, accompanying files, or a
  stable link.

## Current non-goals and planned design areas

The engine does not currently provide a backend/account service, networked multiplayer authority, runtime LLM, ECS, SQL query layer, or a general-purpose database client for UI. These are descriptions of the present implementation, not permanent bans.

The Save migration product surface described above is implemented: supported
identities have checked-in canonical bytes, single-slot inspection and bounded
backup/recovery are player-accessible, and the maintained four-fixture corpus
runs through Story lifecycle and four-runtime parity gates. Opaque low-level
custom runtime controls and explicit legacy prepare-callback callers remain
outside the composite migration guarantee. PF5/M3 is complete; current/next work
is owned only by the [production-floor sequence](plans/2026-07-30-production-floor-sequence.md).

The script-language decision is durable: Story, Module, Narrative, UI, and official Hotfix code use TypeScript/JavaScript. SillyMaker does not plan Ren'Py DSL/Save compatibility, a custom script interpreter, or an untrusted-code security sandbox. Direct Host-global access remains possible JavaScript but is outside the supported engine API.

The Semantic Stage family (contracts, reducer, projection, transitions, reconciler, components), PendingInteraction, audio intent/presentation, the typed Timeline, the DevTools data plane (runtime inspector and Narrative graph), Cat Cafe's Story-local script-node Stage preview, Player rollback, the VN player systems, the capability-gated debug-command channel, and named-scenario `story simulate --trace` plus `story diff` tooling above are implemented. A generic arbitrary-snapshot preview, Timeline scrubber, audio/transition inspection, editors, the bounded Presentation Scene Graph, and advanced media/renderer adapters beyond the delivered audio intent stack remain planned in the [engine roadmap](roadmap.md); the retired V1 scene-graph stage system (StageSceneGraph, hit maps, spatial interaction surfaces, character rigs) was deleted with the first PoC rather than ported.

State access and persistence may be redesigned. The current exploratory direction is recorded in [the typed StateStore proposal](proposals/typed-state-store.md). Any adopted design should replace or simplify existing machinery rather than create two competing authoritative states.

The Engine Lab Story is a conformance rig, not a product design. Its module split, thresholds, and script exist to exercise engine contracts; new games should not copy them as gameplay guidance.
