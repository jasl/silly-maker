## Story authoring and resolution

- Typed `GamePackage`, `GameSimulation`, and `GameplayModule` definitions.
- A dedicated `@sillymaker/base/authoring` entry with `createRuntimeSchemaV1` (canonical-JSON output, deep-freeze, structured failures) and `fromStandardSchemaV1`, the official Zod adapter accepting any Standard Schema V1 implementation without leaking library types.
- `createGameAuthoringKitV1`: typed capability tokens, `requires`/`provides` with provider factories that build narrow read-only ports from the module's own State slice, a validated capability availability DAG plus an independent `initializesAfter` lifecycle DAG (stable diagnostic codes for missing/duplicate providers, cycles, and undeclared token access), stateful/stateless module helpers (a stateful module declares a `reducers` map from domain-event kinds to folds over its own slice), and composition into ordinary low-level module bindings. The low-level `defineGameplayModule`/`defineGameSimulation` API remains the escape hatch; one composition owns one resolved module graph.
- A composition-level transaction runner (`createTransactionRunner`) for cross-module atomic commands under the domain-event model (parallel-monitors lane M1, 2026-08-20): `read(token)` observes the command-start Snapshot, the handler performs every gameplay refusal via `reject(...)` before emitting, and `emit(event)` journals a decided outcome after validating it once against the Story `eventSchema` — `emit` itself never rejects. After `complete()`, the engine folds the journal deterministically: events replay in emission order, and within one event the subscribed module reducers run in locale-independent UTF-16 code-unit module-ID order, each folding its own slice forward, so declaration order or Host locale never changes fold order, the candidate Snapshot, CommandLog, or replay. Events with no subscribed reducer are journal-only broadcast evidence (UI projections, tests). The engine owns slice replacement, schema/invariant validation, journal collection, commit/reject/fault envelopes (the committed envelope carries the event journal as `events`), and RNG/sequence rollback. `commitAttemptV1`/`rejectAttemptV1`/`faultAttemptV1` are also public for hand-written executors.
- Engine-owned Strict Canonical Data admission at every public Session/Simulation/CommandLog command ingress and authoritative replay: one descriptor-safe command traversal rejects symbol-keyed members, extra own array properties, custom array prototypes, and represented accessors while generating the unchanged canonical bytes plus a new path-local ordinary-data projection. Only that projection is frozen and delivered to the executor/log/replay driver; admission neither retains nor freezes the upstream normalized identity (schema helpers may already have frozen their own output), shared aliases expand per canonical path, and ingress-attached Proxy/private/WeakMap state cannot cross the boundary. One exact-projection operation receipt prevents duplicate traversal. A malformed command fails before queue/status publication, RNG, Snapshot digest/freeze, continuity, or driver construction; Story schema/domain failures keep their existing result contracts, while canonical violations use root-exported `CanonicalJsonError` with stable `code` and JSON-Pointer `path`. Authoritative replay captures every source/command slot once, runtime-validates `game | debug`, prepares the projection vector, and freezes none until every entry passes; even a valid `null` projection is submitted without rereading its slot. Public `canonicalJsonBytes`, digest, Save, Debug Bundle, and valid CommandLog/replay bytes remain unchanged; best-effort inspection is unchanged. Direct generic CommandLog extras are conditionally projected/frozen as independent metadata while retaining public key order; enumerable collisions with engine-owned entry fields reject synchronously, and the standard Session path has no metadata traversal.
- Engine-owned finalized-evidence admission for Session, independent CommandLog, authoritative replay, Debug validation failures, and structurally attempt-shaped direct Simulation results: descriptor-only outer capture preserves getter-zero behavior and Standard Core's zero-RNG precedence; every evidence collection captures one own array `length` data descriptor and validates indices against that fixed length, so Proxy virtual length cannot alter the vector. Declared domain-event/rejection/debug-error schemas normalize each item before one Snapshot-free Strict Canonical Data projection traversal and freeze. The admitted projection flows into an engine-rebuilt attempt, and an exact admitted-attempt package-internal one-shot handoff carries it to CommandLog; admission itself neither retains nor freezes upstream normalized evidence, while a schema's own freeze contract remains in force and result/pre-attempt Snapshots deliberately retain authoritative identity. No public evidence hook, receipt, fault schema, result branch, or `GameSimulation` revision was added. Failure occurs before candidate Snapshot integrity/freeze/digest, log continuity, install, or publication. Session invokes its existing unexpected-fault normalizer once; only a valid same-Snapshot canonical fault fallback is logged and pauses the Session, while an invalid fallback rejects without recursive normalization or authoritative mutation. Opaque non-attempt `GameSimulationV1` generic results remain unchanged, and valid Snapshot/digest/Save/replay/DebugBundle bytes retain their existing formats.
- The bounded Strict JSON parser classifies number tokens from exact decimal coefficient/scale/exponent data before final conversion. Mathematical safe integers keep accepting alternate spellings such as `1.0`, `1e0`, and trailing-zero cancellation; rounded fractions reject as `number.not_integer`, true negative-zero spellings as `number.negative_zero`, and exact out-of-range integers (including non-finite conversion outcomes) as `number.unsafe_integer`. The enclosing byte limit is the resource bound, no Decimal/BigInt runtime or exponent-sized allocation is introduced, and decoder failure exposes no partial value. Valid Save metadata vectors, Save/DebugBundle normalization, canonical bytes, and digests remain unchanged.
- Standard Core treats Story-owned `createBootstrapInput` as a Host-ingress adapter. Before reading the RNG seed or invoking root/module initializers, one package-internal Strict Canonical Data traversal builds a path-local ordinary projection and one recursive freeze seals that engine-owned handoff. The adapter raw value remains caller-owned and unfrozen; shared aliases expand per path, cycles reject, and Proxy/private/WeakMap identity state cannot enter authoritative initialization. Construction, queued restart, and the captured extension `createInitialSnapshot` helper share the same stage order and failure precedence. The seed is descriptor-read and parsed once from the admitted projection, then the same frozen identity reaches the resolved root and each stateful module initializer in tuple order. Canonical, freeze, seed, Story/schema, and Snapshot failures retain their existing public channels and cannot install a partial Session, replay base, or persistence anchor. This adds no public bootstrap schema, receipt, or hook and preserves valid initial Snapshot, digest, Save, and replay bytes.
- A shared versioned `DiagnosticEnvelopeV1` (stable code, severity, phase, subject, JSON-pointer location, suggestion, Strict JSON details) used by authoring/definition/resolution failures, plus `collectGamePackageDiagnosticsV1` to aggregate a package's failures as structured diagnostics with human and JSON output.
- Separate simulation (`rule | value`) and presentation (`value | text | asset`) patch surfaces.
- Validated, frozen resolution with Story, engine, state-contract, simulation, presentation, asset, and patch-set identity.
- Story-local schemas, deterministic rule providers, command executors, queries, ViewModel projectors, scene graphs, catalogs, and renderer contributions.
- Optional lazily loaded Story tooling and tooling UI.

- The Base application composer (`@sillymaker/base/runtime`): `defineCoreGameApplicationV1` declares a Host-neutral core application (GamePackage entry, semantic adapter, validators, diagnostics extensions — no React, no Host handle); `resolveCoreGameApplicationV1` produces an immutable reusable resolved definition with structured failure reporting; `createCoreGameApplicationInstanceV1` creates a disposable instance that owns the Session, semantic port, persistence lease, diagnostics buffer, and lifecycle (`restart`). Failed construction and idempotent disposal leave no active owner or listener. Each instance maintains an instance-local presentation anchor/epoch that advances when the authoritative replay base is replaced (load/import/restart/debug anchor, with origin labels) and never enters SemanticPublication, semantic revisions, or Agent transcripts; `bindToCurrentEpoch` guards stale presentation callbacks structurally. `GameSession` keeps its current Snapshot digest as private derived evidence: committed Snapshots are frozen before one post-state digest, rejected/faulted attempts reuse the current digest, and every replay-base replacement refreshes Snapshot, CommandLog anchor, and digest together. The hot Session path retains object-identity and digest-chain checks without re-traversal, while the public low-level `createCommandLogV1` keeps full digest self-audit. Persistence can reuse that derived evidence only for the exact installed Snapshot under the exact Session runtime-control identity; custom/wrapped controls, cloned Snapshots, schema-normalized copies, and physical readback keep independent digest validation. The built-in Save repository also binds a successful exact write attempt to one private one-shot expected-byte receipt, so write verification can compare the physical readback without re-encoding the same current envelope; custom/decorated repositories retain the independent expected-encoding fallback, and lease, schema, digest, revision, and raw-byte readback checks remain in force. Built-in Save encoding performs canonical serialization and Strict depth/node/collection/string/dangerous-key checks in the same internal traversal; decoding untrusted bytes still uses the complete Strict parser before schema and digest validation. Autosave is an injectable policy (`every_commit` default, or `debounced` with `delayMs`, optional `checkpointEveryCommands`, an injectable scheduler for deterministic tests, and `flushAutoSave` for lifecycle hosts). Debounced admission requires `delayMs` to be a non-negative safe integer other than `-0`, and an optional checkpoint to be a positive safe integer; invalid policies fail before Session creation, persistence lease acquisition, timer access, or Host writes. A flush registers the exact current authoritative Snapshot at the Session queue front and succeeds only for that candidate's verified `auto.current` receipt. A same-sequence manual save cannot mask failure, initial and replacement Snapshots are eligible without a new command, duplicate exact captures reuse in-flight or already-verified identity, failed current attempts remain retryable, and replay-base replacement supersedes old-epoch receipts. Explicit slot saves remain available under any policy. Standard Core rejects a zero `xorshift32-v1` bootstrap/restored cursor before Story initial-state construction, command finalization, replay, or authoritative replacement; Save and DebugBundle codecs preserve `rng.invalid_state`, failed boot-resume keeps the fresh Session usable, and valid RNG/Snapshot/CommandLog/Save bytes remain unchanged. Low-level generic Session and replay constructors remain algorithm-agnostic escape hatches; no public admission hook was added. Low-level constructors (`createGameSessionV1`, `createPersistenceServiceV1`, `createSemanticGamePortV1`) stay public as escape hatches.
- Persistence safepoints and in-flight spans V1 ([parallel-monitors lane](proposals/parallel-monitors.md) M3, 2026-08-20): an application may declare `persistenceSafepoint: { classify, maxInFlightCommits }` on `defineCoreGameApplicationV1` — `classify` is a deterministic read of committed authoritative state returning `safepoint` | `in_flight` (derive it from existing vocabulary: the Engine Lab classifies a pending `presentation_barrier` as in-flight), and `maxInFlightCommits` (1..256) is the admission-enforced span bound (`parsePersistenceSafepointPolicyV1`; an unbounded or malformed declaration fails resolution with `persistence_safepoint.invalid` before any Session or persistence owner exists). While a span is open the orchestrator defers autosave — under `every_commit` an in-flight commit never becomes a candidate; under `debounced` the last safepoint candidate and any timer already running for it stay in place — and `flushAutoSave` falls back to the most recent safepoint Snapshot of the current anchor era (with none, the flush writes nothing and the stored pre-span record remains the crash-recovery target). Player-slot saves inside a span reject with the `in_flight` code (the default Save overlay renders the Story's `rejected.in_flight` label); loads stay available, and a load/import/restart anchor replacement resets span tracking so a pre-replacement safepoint Snapshot can never write into the new era. The bound keeps spans honest: exceeding it forfeits the inhibit with one `persistence.safepoint_span_exceeded` diagnostic until the next safepoint commit, and a throwing or malformed classifier reports `persistence.safepoint_classify_failed` and fails open as a safepoint — a malfunctioning declaration can never starve the Save. The classification never enters authoritative state, Saves, digests, or replay: every commit remains complete, valid, and replayable — a span only expresses a re-entry preference. It is orthogonal to the UI-level `saveGuard` (which disables the manual-save control with a stated reason over the live publication): the guard is presentation intent, the safepoint policy is orchestration that also covers autosave and flush. The barrier's `loadRecovery` vocabulary stays authoritative for Saves that do capture a pending barrier (bound forfeits, legacy records, imports) — the Engine Lab's default-UI suite stages such a legacy record and proves it still settles on load.

## Runtime

- `@sillymaker/base/story` is the Story authoring prelude: the current generation of every commonly authored contract re-exported under unversioned names (`SemanticStageState`, `StageMutation`, `PendingInteraction`, `NarrativeGraph`, `reduceStageMutations`, `evaluateInteractionResolution`, `defineCoreGameApplication`, …). It is a pure alias layer — a type-test matrix proves each alias identical to its versioned original — and it moves to a new generation together with the family it aliases. Versioned names remain the source of truth inside the engine; the superseded hand-assembly surfaces (`createGameRuntimeV1`, `createGameBootstrapControllerV1`/`Loader`, `createGameApplicationV1`, `useRuntimePresentationV1`) were removed once the composer path replaced their last consumer.

- One authoritative `GameSession` queue for gameplay dispatch and State replacement.
- Immutable, schema-validated `GameSnapshot` values; the session deep-freezes every installed Snapshot so live mutation attempts throw.
- Serializable purpose-labelled PRNG with rollback-safe command attempts.
- Structured commit, rejection, validation, and fault outcomes.
- Static module composition with explicit State ownership and dependency validation.
- Semantic preview/dispatch and immutable subscription publications for UI and automation.
- Lifecycle restart/rebootstrap and replay-base replacement.
- Semantic Stage contracts: versioned `SemanticStageStateV1` (ordered layers, stable `<layerId, tag>` entries, integer logical placement/appearance/camera targets) as plain canonical Save data, plus a pure atomic `reduceStageMutationsV1` batch reducer (`show`/`replace`/`hide`/`clearLayer`/`clearStage`/`setPlacement`/`setAppearance`/`setLayerTransform`/`setCamera`) that either commits a complete valid successor or rejects without touching the input state.
- Non-authoritative `StageRenderTargetV1` projection: a Story `StageContentCatalogV1` deterministically resolves semantic content into renderer IDs, asset IDs, accessible names, and Strict JSON props; unresolved content binds a code-native fallback renderer with structured diagnostics. The render target is rebuilt from State plus catalog and never enters a Save.
- Stage-driven projection wiring: Story game views may carry `SemanticStageStateV1` through the semantic publication (headless agents observe the semantic stage target), the Story UI projector rebuilds the render target every projection, and settled `requiredAssetIds` track the current target exactly — superseded assets leave the demand when the stage retargets.
- Stage transition contracts: plain, validated `StageTransitionDefinitionV1` data (cut/crossfade/slide/motion, duration/easing, `block`/`target_active`/`skip_to_end` input policies, `settle_and_retarget`/`cancel_to_target` interruption, reduced-motion settle-or-fallback, immediate-or-bounded asset readiness, optional completion acknowledgment) plus a Story `StageTransitionCatalogV1` resolving old-to-new target changes. Definitions never enter the saveable stage state, and playing them never modifies gameplay State.
- `PendingInteractionV1`: the saveable interaction boundary (say, choice, hold, presentation barrier, and schema-registered custom surfaces) with three separated identities — author-stable `definitionId`, author-controlled `seenRevision`, and a per-entry-unique `occurrenceId` from a deterministic Story-owned sequence. A choice must have at least one option; the contract sets no upper bound on option count. Untrusted Save input stays bounded at admission by `saveJsonLimitsV1` (bytes, array items, nodes, depth, string length), and custom interaction JSON additionally by depth, string length, and member count. `evaluateInteractionResolutionV1` is the single occurrence-fenced evaluator shared by the action catalog, preview, and queue-front dispatch; stale occurrences, wrong kinds, unknown or disabled choices, mismatched barrier transitions, and out-of-schema custom payloads reject without touching State. Renderer promises and callbacks never enter State or Saves.
- The authoritative hold clock (accepted 2026-08-19, [proposal](proposals/authoritative-hold-clock.md); time verb unified 2026-08-20 by the [parallel-monitors lane](proposals/parallel-monitors.md) M0): `hold` holds the screen between two lines for an authoritative duration — `totalMs`/`remainingMs` as positive integer milliseconds plus the author's `skippable` flag (original 60fps frame counts convert at Story compile time). Elapsed time reaches the session through the single session-level time verb `TimeTickV1` (`parseTimeTickV1`/`evaluateTimeTickV1`; story facade `parseTimeTick`/`evaluateTimeTick`): a tick carries `elapsedMs` plus an optional `expectedHoldOccurrenceId` hold fence — fenced ticks fold the pending hold and reject as stale once the occurrence expires, unfenced ticks are accepted unconditionally and never fold a hold — they settle the session-global time consumers (declared authoritative monitors; a hold-free, monitor-free Story commits them as observable no-ops). Holds are pure time-settlement boundaries: every input resolution against a hold rejects with `interaction.kind_mismatch`, and the retired `hold_tick` resolution kind no longer parses. `applyElapsedToHoldV1` (facade `applyElapsedToHold`) is the shared runner arithmetic: it consumes `min(elapsedMs, remainingMs)` (overshoot clamps instead of rejecting), keeps the same boundary occurrence while a remainder is left, and expires into the node's successor on the tick that reaches zero (no separate `hold_expire`). The terminal state depends only on the millisecond sum, never on Host batch splits; wall clocks stay out of State, Saves, digests, and replay. The Story's narrative surface binds the `dispatchTime` port next to `dispatchResolution` (nullable for hold-free stories); the Narrative Host's hold-expiry controller settles expiry as one fenced tick commit, and a skippable hold's player input folds the remainder the same way via the retained `narrative.resume` physical action id. ## Content database

- Story-defined static data tables: `defineContentTableV1` validates a table at definition (table-id pattern, per-row RuntimeSchema parsing — typically zod via `fromStandardSchemaV1` — unique non-empty string primary keys, row limits); `createContentDatabaseV1` validates cross-table references at construction and exposes typed read-only views: `byId` (KV), `findMany`/`findFirst` with `where` conditions (eq/ne/in, numeric comparisons, array membership) and ordering, plus `collectTextIds` for text-catalog joins. ## Gameplay primitives

- Event pool: `parseEventConditionV1` validates restricted serializable condition trees (number/flag/label leaves, all/any/not composition, depth and branch bounds). ## Current non-goals and planned design areas

The engine does not currently provide a backend/account service, networked multiplayer authority, runtime LLM, ECS, SQL query layer, or a general-purpose database client for UI. These are descriptions of the present implementation, not permanent bans.

The Save migration product surface described above is implemented: supported
identities have checked-in canonical bytes, single-slot inspection and bounded
backup/recovery are player-accessible, and the maintained four-fixture corpus
runs through Story lifecycle and four-runtime parity gates. Opaque low-level
custom runtime controls and explicit legacy prepare-callback callers remain
outside the composite migration guarantee. PF5/M3 is complete; current/next work
is owned only by the [production-floor sequence](plans/2026-07-30-production-floor-sequence.md).

The script-language decision is durable: Story, Module, Narrative, UI, and official Hotfix code use TypeScript/JavaScript. SillyMaker does not plan Ren'Py DSL/Save compatibility, a custom script interpreter, or an untrusted-code security sandbox. Direct Host-global access remains possible JavaScript but is outside the supported engine API.

The Semantic Stage family (contracts, reducer, projection, transitions, reconciler, components), PendingInteraction, audio intent/presentation, the typed Timeline, the DevTools data plane (runtime inspector and Narrative graph), Cat Cafe's Story-local script-node Stage preview, Player rollback, the VN player systems, the capability-gated debug-command channel, and named-scenario `story simulate --trace` plus `story diff` tooling above are implemented. A generic arbitrary-snapshot preview, Timeline scrubber, audio/transition inspection, editors, the bounded Presentation Scene Graph, and advanced media/renderer adapters beyond the delivered audio intent stack remain planned in the [engine roadmap](roadmap.md); the retired V1 scene-graph stage system (StageSceneGraph, hit maps, spatial interaction surfaces, character rigs) was deleted with the first PoC rather than ported.

State access and persistence may be redesigned. The current exploratory direction is recorded in [the typed StateStore proposal](proposals/typed-state-store.md). Any adopted design should replace or simplify existing machinery rather than create two competing authoritative states.

The Engine Lab Story is a conformance rig, not a product design. Its module split, thresholds, and script exist to exercise engine contracts; new games should not copy them as gameplay guidance.
