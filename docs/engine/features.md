## Story authoring and resolution

- Typed `GamePackage`, `GameSimulation`, and `GameplayModule` definitions.
- A dedicated `@sillymaker/base/authoring` entry with `createRuntimeSchemaV1` (canonical-JSON output, deep-freeze, structured failures) and `fromStandardSchemaV1`, the official Zod adapter accepting any Standard Schema V1 implementation without leaking library types.
- `createGameAuthoringKitV1`: typed capability tokens, `requires`/`provides` with provider factories that build narrow read-only ports from the owner's State slice, a validated capability availability DAG plus an independent `initializesAfter` lifecycle DAG (stable diagnostic codes for missing/duplicate providers, cycles, and undeclared token access), stateful/stateless module helpers with derived proposal schemas, and composition into ordinary low-level module bindings. The low-level `defineGameplayModule`/`defineGameSimulation` API remains the escape hatch; one composition owns one resolved module graph.
- A composition-level transaction runner (`createTransactionRunner`) for cross-owner atomic commands: `read(token)` observes the command-start Snapshot, each owner accepts at most one proposal (duplicates fault with a stable diagnostic), and completed staged proposals apply in locale-independent UTF-16 code-unit module-ID order so declaration order or Host locale never changes apply/fact order, the candidate Snapshot, CommandLog, or replay. The engine owns slice replacement, schema/invariant validation, fact collection, commit/reject/fault envelopes, and RNG/sequence rollback. `commitAttemptV1`/`rejectAttemptV1`/`faultAttemptV1` are also public for hand-written executors.
- Engine-owned Strict Canonical Data admission at every public Session/Simulation/CommandLog command ingress and authoritative replay: one descriptor-safe command traversal rejects symbol-keyed members, extra own array properties, custom array prototypes, and represented accessors while generating the unchanged canonical bytes plus a new path-local ordinary-data projection. Only that projection is frozen and delivered to the executor/log/replay driver; admission neither retains nor freezes the upstream normalized identity (schema helpers may already have frozen their own output), shared aliases expand per canonical path, and ingress-attached Proxy/private/WeakMap state cannot cross the boundary. One exact-projection operation receipt prevents duplicate traversal. A malformed command fails before queue/status publication, RNG, Snapshot digest/freeze, continuity, or driver construction; Story schema/domain failures keep their existing result contracts, while canonical violations use root-exported `CanonicalJsonError` with stable `code` and JSON-Pointer `path`. Authoritative replay captures every source/command slot once, runtime-validates `game | debug`, prepares the projection vector, and freezes none until every entry passes; even a valid `null` projection is submitted without rereading its slot. Public `canonicalJsonBytes`, digest, Save, Debug Bundle, and valid CommandLog/replay bytes remain unchanged; best-effort inspection is unchanged. Direct generic CommandLog extras are conditionally projected/frozen as independent metadata while retaining public key order; enumerable collisions with engine-owned entry fields reject synchronously, and the standard Session path has no metadata traversal.
- Engine-owned finalized-evidence admission for Session, independent CommandLog, authoritative replay, Debug validation failures, and structurally attempt-shaped direct Simulation results: descriptor-only outer capture preserves getter-zero behavior and Standard Core's zero-RNG precedence; every evidence collection captures one own array `length` data descriptor and validates indices against that fixed length, so Proxy virtual length cannot alter the vector. Declared fact/rejection/debug-error schemas normalize each item before one Snapshot-free Strict Canonical Data projection traversal and freeze. The admitted projection flows into an engine-rebuilt attempt, and an exact admitted-attempt package-internal one-shot handoff carries it to CommandLog; admission itself neither retains nor freezes upstream normalized evidence, while a schema's own freeze contract remains in force and result/pre-attempt Snapshots deliberately retain authoritative identity. No public evidence hook, receipt, fault schema, result branch, or `GameSimulation` revision was added. Failure occurs before candidate Snapshot integrity/freeze/digest, log continuity, install, or publication. Session invokes its existing unexpected-fault normalizer once; only a valid same-Snapshot canonical fault fallback is logged and pauses the Session, while an invalid fallback rejects without recursive normalization or authoritative mutation. Opaque non-attempt `GameSimulationV1` generic results remain unchanged, and valid Snapshot/digest/Save/replay/DebugBundle bytes retain their existing formats.
- The bounded Strict JSON parser classifies number tokens from exact decimal coefficient/scale/exponent data before final conversion. Mathematical safe integers keep accepting alternate spellings such as `1.0`, `1e0`, and trailing-zero cancellation; rounded fractions reject as `number.not_integer`, true negative-zero spellings as `number.negative_zero`, and exact out-of-range integers (including non-finite conversion outcomes) as `number.unsafe_integer`. The enclosing byte limit is the resource bound, no Decimal/BigInt runtime or exponent-sized allocation is introduced, and decoder failure exposes no partial value. Valid Save metadata vectors, Save/DebugBundle normalization, canonical bytes, and digests remain unchanged.
- Standard Core treats Story-owned `createBootstrapInput` as a Host-ingress adapter. Before reading the RNG seed or invoking root/module initializers, one package-internal Strict Canonical Data traversal builds a path-local ordinary projection and one recursive freeze seals that engine-owned handoff. The adapter raw value remains caller-owned and unfrozen; shared aliases expand per path, cycles reject, and Proxy/private/WeakMap identity state cannot enter authoritative initialization. Construction, queued restart, and the captured extension `createInitialSnapshot` helper share the same stage order and failure precedence. The seed is descriptor-read and parsed once from the admitted projection, then the same frozen identity reaches the resolved root and each stateful module initializer in tuple order. Canonical, freeze, seed, Story/schema, and Snapshot failures retain their existing public channels and cannot install a partial Session, replay base, or persistence anchor. This adds no public bootstrap schema, receipt, or hook and preserves valid initial Snapshot, digest, Save, and replay bytes.
- A shared versioned `DiagnosticEnvelopeV1` (stable code, severity, phase, subject, JSON-pointer location, suggestion, Strict JSON details) used by authoring/definition/resolution failures, plus `collectGamePackageDiagnosticsV1` to aggregate a package's failures as structured diagnostics with human and JSON output.
- Separate simulation (`rule | value`) and presentation (`value | text | asset`) patch surfaces.
- Validated, frozen resolution with Story, engine, state-contract, simulation, presentation, asset, and patch-set identity.
- Story-local schemas, deterministic rule providers, command executors, queries, ViewModel projectors, scene graphs, catalogs, and renderer contributions.
- Optional lazily loaded Story tooling and tooling UI.

- The Base application composer (`@sillymaker/base/runtime`): `defineCoreGameApplicationV1` declares a Host-neutral core application (GamePackage entry, semantic adapter, validators, diagnostics extensions — no React, no Host handle); `resolveCoreGameApplicationV1` produces an immutable reusable resolved definition with structured failure reporting; `createCoreGameApplicationInstanceV1` creates a disposable instance that owns the Session, semantic port, persistence lease, diagnostics buffer, and lifecycle (`restart`). The hot Session path retains object-identity and digest-chain checks without re-traversal, while the public low-level `createCommandLogV1` keeps full digest self-audit. Persistence can reuse that derived evidence only for the exact installed Snapshot under the exact Session runtime-control identity; custom/wrapped controls, cloned Snapshots, schema-normalized copies, and physical readback keep independent digest validation. The built-in Save repository also binds a successful exact write attempt to one private one-shot expected-byte receipt, so write verification can compare the physical readback without re-encoding the same current envelope; custom/decorated repositories retain the independent expected-encoding fallback, and lease, schema, digest, revision, and raw-byte readback checks remain in force. Built-in Save encoding performs canonical serialization and Strict depth/node/collection/string/dangerous-key checks in the same internal traversal; decoding untrusted bytes still uses the complete Strict parser before schema and digest validation. Autosave is an injectable policy (`every_commit` default, or `debounced` with `delayMs`, optional `checkpointEveryCommands`, an injectable scheduler for deterministic tests, and `flushAutoSave` for lifecycle hosts). Debounced admission requires `delayMs` to be a non-negative safe integer other than `-0`, and an optional checkpoint to be a positive safe integer; invalid policies fail before Session creation, persistence lease acquisition, timer access, or Host writes. A flush registers the exact current authoritative Snapshot at the Session queue front and succeeds only for that candidate's verified `auto.current` receipt. A same-sequence manual save cannot mask failure, initial and replacement Snapshots are eligible without a new command, duplicate exact captures reuse in-flight or already-verified identity, failed current attempts remain retryable, and replay-base replacement supersedes old-epoch receipts. Explicit slot saves remain available under any policy. Standard Core rejects a zero `xorshift32-v1` bootstrap/restored cursor before Story initial-state construction, command finalization, replay, or authoritative replacement; Save and DebugBundle codecs preserve `rng.invalid_state`, failed boot-resume keeps the fresh Session usable, and valid RNG/Snapshot/CommandLog/Save bytes remain unchanged. Low-level generic Session and replay constructors remain algorithm-agnostic escape hatches; no public admission hook was added. Low-level constructors (`createGameSessionV1`, `createPersistenceServiceV1`, `createSemanticGamePortV1`) stay public as escape hatches.

Stories supply only their semantic adapter (queries, projections, action catalog, previews, invocation mapping); the harness provides observe/preview/dispatch/waitForIdle, a deterministic trace, state digests, the persistence port, the underlying `application` instance, an admin surface (command log, authoritative replay, capability-gated debug control, explicit `inspectForTest`), and structured outcomes after disposal. The normal surface exposes no raw Snapshot or State setter. A separate package-internal memory baseline holds one neutral 1k-entity Session across 1,200 real cross-owner commits, crosses the 200-entry CommandLog retention boundary, and records process-isolated before/after-GC samples without exposing memory or instrumentation hooks to Story consumers; raw traversal, Save serialization, Strict JSON, memory, and GC instrumentation remain package-internal. ## Runtime

- `@sillymaker/base/story` is the Story authoring prelude: the current generation of every commonly authored contract re-exported under unversioned names (`SemanticStageState`, `StageMutation`, `PendingInteraction`, `NarrativeGraph`, `reduceStageMutations`, `evaluateInteractionResolution`, `defineCoreGameApplication`, …). It is a pure alias layer — a type-test matrix proves each alias identical to its versioned original — and it moves to a new generation together with the family it aliases. Versioned names remain the source of truth inside the engine; the superseded hand-assembly surfaces (`createGameRuntimeV1`, `createGameBootstrapControllerV1`/`Loader`, `createGameApplicationV1`, `useRuntimePresentationV1`) were removed once the composer path replaced their last consumer.

- One authoritative `GameSession` queue for gameplay dispatch and State replacement.
- Immutable, schema-validated `GameSnapshot` values; the session deep-freezes every installed Snapshot so live mutation attempts throw.
- Serializable purpose-labelled PRNG with rollback-safe command attempts.
- Structured commit, rejection, validation, and fault outcomes.
- Static module composition with explicit State ownership and dependency validation.
- Semantic preview/dispatch and immutable subscription publications for UI and automation.
- Lifecycle restart/rebootstrap and replay-base replacement.
- Semantic Stage contracts: versioned `SemanticStageStateV1` (ordered layers, stable `<layerId, tag>` entries, integer logical placement/appearance/camera targets) as plain canonical Save data, plus a pure atomic `reduceStageMutationsV1` batch reducer (`show`/`replace`/`hide`/`clearLayer`/`clearStage`/`setPlacement`/`setAppearance`/`setLayerTransform`/`setCamera`) that either commits a complete valid successor or rejects without touching the input state.
- Non-authoritative `StageRenderTargetV1` projection: a Story `StageContentCatalogV1` deterministically resolves semantic content into renderer IDs, asset IDs, accessible names, and Strict JSON props; unresolved content binds a code-native fallback renderer with structured diagnostics. The render target is rebuilt from State plus catalog and never enters a Save.
- Stage-driven projection wiring: Story game views may carry `SemanticStageStateV1` through the semantic publication (headless agents observe the semantic stage target), the Story UI projector rebuilds the render target every projection, and settled `requiredAssetIds` track the current target exactly — superseded assets leave the demand when the stage retargets.
- Stage transition contracts: plain, validated `StageTransitionDefinitionV1` data (cut/crossfade/slide/motion, duration/easing, `block`/`target_active`/`skip_to_end` input policies, `settle_and_retarget`/`cancel_to_target` interruption, reduced-motion settle-or-fallback, immediate-or-bounded asset readiness, optional completion acknowledgment) plus a Story `StageTransitionCatalogV1` resolving old-to-new target changes. Definitions never enter the saveable stage state, and playing them never modifies gameplay State.
- `PendingInteractionV1`: the saveable interaction boundary (say, choice, pause, presentation barrier, and schema-registered custom surfaces) with three separated identities — author-stable `definitionId`, author-controlled `seenRevision`, and a per-entry-unique `occurrenceId` from a deterministic Story-owned sequence. `evaluateInteractionResolutionV1` is the single occurrence-fenced evaluator shared by the action catalog, preview, and queue-front dispatch; stale occurrences, wrong kinds, unknown or disabled choices, mismatched barrier transitions, and out-of-schema custom payloads reject without touching State. Renderer promises and callbacks never enter State or Saves.
- Typed audio media contracts: `AudioAssetSlotV1`/`AudioProviderEntryV1`/`resolveAudioManifestV1` keep music, ambient, SFX, and voice as their own contract (never images) with declared byte length and sha256 for response verification and a silence fallback. The saveable `AudioIntentV1` carries BGM/ambient channel targets (loop, permille gain, millisecond fades) and the current voice tied to its say interaction with a `stop_on_advance`/`sustain` policy; Saves reference stable asset IDs only.
- `AssetDemandPlanV1`: the explicit demand-plan contract (blocking/opportunistic priority, load group, concurrency budget, retry/backoff, retention) that loaders consume instead of accumulating one-shot requests; the budgeted plan scheduler integrates as media volumes grow.
- Typed Timeline contracts (R5): JSON-safe `TimelineDefinitionV1` (sequence/parallel/wait/tween/repeat/event over integer overlay channels — offsets, scale, opacity — targeting stage entries or the camera) with the `timelineV1` builder producing the identical contract as a hand-written literal. `parseTimelineDefinitionV1` rejects unknown kinds, invalid durations/easings, unbounded or over-deep repeats, and parallel branches writing the same channel; pure `evaluateTimelineAtV1`/`timelineDurationV1` make sampling deterministic and timer-free.
- Authorable Motion contracts: `MotionDocumentV1` is a standalone versioned keyframe document (`format: "sillymaker.motion"`, typically a `*.motion.json` source asset) — integer keyframe tracks over the four overlay channels with per-segment easing (linear/quad/cubic in-out families, `ease_out_back` overshoot, permille cubic-bezier control points), first/last keyframes pinned to 0/1000‰, and strippable `authoring` metadata (`generated`/`human_tuned`, `locked`, notes) for humans and editing tools. `parseMotionDocumentV1` performs strict exact-record admission with structured paths; `motionStageTransitionV1` normalizes a document into a `kind: "motion"` transition (the document owns curves and timing — duration derives from it; the binding owns edge behavior); pure `sampleMotionAtV1` returns identical overlay values for identical times, holding the first keyframes through `delayMs`. Motion data never enters gameplay State, Saves, digests, or replay. The Engine Lab character entrance and the Cat Cafe cat entrance are its two consumers.
- SillyMaker Studio (VN Scene Workspace A2): a dev-only project-level scene workspace at `/__sillymaker/studio/` (boot with `deno task author <application-id>` or `deno task dev`). V1 panels: a scene navigator listing every `*.scene.json` (opening a scene needs no story progress), a detached real-renderer canvas (settled target — no Session, no reconciler, no gameplay state), a placement inspector (x/y/scale/mirror/zOrder; numbers are the precision entry), direct manipulation on the canvas (VN Scene Workspace A3: geometry-derived selection boxes with anchor dot, drag-to-place writing integer logical coordinates — pointer ÷ preview scale, snapped to canvas edges/centers with guide lines, clamped inside the canvas — plus a corner scale handle), a cue table with replay-through-cue and per-cue motion binding selects, and the embedded Motion Workbench with cue-derived preview cases. - Scene authoring documents (VN Scene Workspace A0): `SceneDocumentV1` is a standalone versioned scene document (`format: "sillymaker.scene"`, a `*.scene.json` source asset under `src/scenes/<scene>/`) declaring the scene's entries — stable `<layerId, tag>` identity, contentId, zOrder, placement, appearance, reusing the exact stage integer bounds — and named cues (`show`/`hide` per entry, each optionally binding one motion asset to exactly that cue's stage edge; hide only removes what is present) emitting ordinary `StageMutationV1` batches byte-identical to hand-written ones — Snapshot/Save/digest/replay are unaffected — plus `cueMayShow`/`mayShow` for stage-node lint annotations, and `openMutations(stage)` (VN Scene Workspace A5 gap 3): the deterministic idempotent batch that opens or reopens the scene — undeclared entries on declared layers hide first, then each declared entry shows/replaces or corrects placement/appearance back to the declared values; layers the document does not declare and declaration-silent fields stay untouched, so "go to scene X" is one accessor call instead of a hand-written hide+show sequence. `sceneStageTransitionBindingsV1` derives exact-match transition bindings (edge kind + layer + entry key + content, transition ids derived `cue.…` → `transition.…`) that compose in front of the Story catalog, replacing Story-global resolver inference — its input accepts per-cue `edges` overrides for edge behavior (input policy, interruption, reduced motion, readiness, acknowledgment; e.g. a barrier-acknowledged blocking entrance), keeping the Document owner of _which_ motion plays and the binding owner of _how_ the edge behaves; `sceneSettledMutationsV1` replays cue order into a detached-preview mutation batch. `story check` lints every scene file (`scene.document_json_invalid`/`scene.document_invalid`/`scene.id_duplicate`/`scene.id_filename_mismatch`/`scene.cue_motion_missing`, and `scene.cue_binding_collision` when two documents bind different motions to one stage edge — composed bindings resolve first-match, so the shadowed motion would silently never play). The Cat Cafe opening (`examples/cat-cafe/src/scenes/opening/`) is the first scene-managed consumer: its placement literals and the "every enter edge" motion inference left the script and transition catalog, and the scene document is that scene's single authoring authority. The starter template's opening (`template/src/scenes/opening/`, VN Scene Workspace A4) is the second: the starter plays out of the box, declares a Studio binding, and keeps mid-scene appearance beats script-owned (V1 cues cover show/hide composition).

- Story meta progress: `PlayerProfileV1.meta` is a monotone `entryId -> value` map on the Host profile (the Seen registry generalized) with `markMeta` on the profile store; it survives every Game Save, restart, and rollback, and legacy profile records parse as empty. Stories own the key vocabulary (album unlocks, endings reached); the cat-cafe album overlay renders content-table entries against profile unlocks.
- Player rollback (R7): an opt-in `CoreRollbackPolicyV1` gives an application a bounded ring of committed Snapshots (default-pinned outcomes — RNG state travels inside every Snapshot, so a rolled-back retry reproduces the same result) with `classify` marking hard-barrier commands (settlements, irreversible beats) that clear every checkpoint behind them. `instance.rollback` exposes `available`/`toPrevious`/`subscribe`; a rollback replaces the authoritative Snapshot, advances the presentation epoch with origin `rollback` (stage, audio, and pending interactions re-project settled), reseeds on load/import/restart, and never touches Saves. Player history and rollback stay distinct from the CommandLog and Debug replay; the Seen registry lives in the Host profile and survives rollback by design. The Engine Lab and the Cat Cafe (contest entry and postgame confirmation as barriers, a HUD one-step-back control) are its two consumers.

- Commit-only transient effects: `CoreSemanticAdapterV1.projectTransientEffects` derives one-shot effect requests (for example SFX) from committed command facts, and the application instance emits them through `subscribeTransientEffects` stamped with a monotonic per-instance sequence and the presentation epoch at commit time. Effects never enter State, Saves, publications, or Agent transcripts, and load/bootstrap publications carry no history.
- `NarrativeHistoryV1`: the bounded player-readable backlog as Story/Narrative authoritative State — it enters Snapshots and Saves, restores to the exact occurrence, and is marked for M3 rollback to travel with the checkpoint Snapshot. - Narrative graph lint and prediction: Stories project their typed TS narrative IR into the JSON-safe `NarrativeGraphV1` (no parser, no DSL — `createNarrativeGraphBuilderV1` and a hand-written literal produce the identical contract). `lintNarrativeGraphV1` reports duplicate nodes, missing entry/successors/call targets, unreachable nodes, pure loops with no interaction boundary, and duplicate interaction definitions as structured diagnostics with stable codes and source/pointer locations. `predictNarrativeDependenciesV1` walks every branch and call from the current cursor under an explicit node/depth/asset budget — it never executes a command, consumes RNG, or decides a hidden choice — and `narrativePredictionToDemandPlanV1` maps the collected text/asset/stage dependencies to an opportunistic prefetch `AssetDemandPlanV1`.

## Content database

- Story-defined static data tables: `defineContentTableV1` validates a table at definition (table-id pattern, per-row RuntimeSchema parsing — typically zod via `fromStandardSchemaV1` — unique non-empty string primary keys, row limits); `createContentDatabaseV1` validates cross-table references at construction and exposes typed read-only views: `byId` (KV), `findMany`/`findFirst` with `where` conditions (eq/ne/in, numeric comparisons, array membership) and ordering, plus `collectTextIds` for text-catalog joins. Numeric ordering compares relational sign without subtraction overflow; string ordering is fixed UTF-16 code-unit order and never consults Host locale. Content is authoring-time data: no runtime mutation, JSON-safe, deterministic, and part of Story identity through the ordinary source-digest path. Mutable game state stays in module state (atomic commits, Saves, rollback) — the static/dynamic boundary is the design's first principle. First real consumer: the cat-cafe example (activities, petting reactions, contest moves, rivals, album entries).

## Gameplay primitives

- Event pool: `parseEventConditionV1` validates restricted serializable condition trees (number/flag/label leaves, all/any/not composition, depth and branch bounds). Evaluation/draw captures each own enumerable numeric-context value once into an engine-owned projection, admits the complete projection as safe integers, and rejects fractional, non-finite, unsafe, or negative-zero values; inherited numeric properties are missing rather than an admission bypass. Draw also captures each candidate id/weight/condition once, then eligibility, accumulation, force, explanation, and selection consume only that projection. Eligible weights accumulate with a pre-add safe-integer overflow check across the complete authoring-order vector, including forced selection; invalid context/overflow fails before RNG or explanation. Valid draws use one purpose-tagged transactional-RNG roll with JSON-safe explanation data (considered, eligible weights, roll, winner), while debug force preserves eligibility and spends no draw. First consumer: the cat-cafe weekly regulars (conditions in content-table rows, draws inside the business transaction, explanations in facts).

## Persistence and compatibility

- Game-shell native-behavior reset (`@sillymaker/ui` `installNativeBehaviorResetV1`, declared per application via `nativeBehaviorReset` on the web UI definition): a "reset CSS" for browser input defaults — suppresses the context menu, text selection, touch callouts, and image drag document-wide so a Player feels like a game shell. Editable controls (`input`/`textarea`/`select`/contenteditable) keep native selection; interactive controls keep native menus and callouts; any subtree opts back in with `data-native-menu` / `data-native-text`. Document-scoped on purpose because Story overlays portal to `document.body`; disposal removes every installed piece. The reset is a presentation floor, not a semantic owner: its Window-bubble listener runs after the document-level pointer adapter, exposes no raw context-menu callback, and yields when that adapter has claimed the event. Remappable right-click stays with the Input Router (`data-secondary-action` on controls, stage `cancel` mapping), while `data-native-menu` is an absolute opt-out and the stage CSS keeps its own selection/zoom/scroll-chaining suppression for the shell subtree. The template enables it by default.
- Desktop-channel persistence preview: `createHttpHostRecordStoreV1` is the browser-side adapter for the trusted local records endpoint. The Deno save server and packaged shell validate same-origin JSON requests, bounded bodies, namespaces, revisions, paths, and stored records; their current JSON-file backend provides optimistic revisions, a serialized in-process queue, and atomic **per-record** replacement. It does not yet prove crash-atomic multi-record commits, cross-process CAS, or a portable collision-free filename mapping for arbitrary record keys, so it remains a preview/reference backend pending the [desktop durability plan](plans/2026-07-30-desktop-persistence-durability.md). `startWebGameApplicationV1` selects the HTTP adapter when the page runs with `?records=local` or the shell injects `__SILLYMAKER_RECORDS__`.
- Usable Desktop packaging preview: `deno task build:desktop` (where the application declares it; `deno task story desktop <app>` from the root) stages a thin shell shipped inside `@sillymaker/tooling`, serves the built Player from embedded `dist/`, injects the local-records signal plus one per-launch capability, and owns a save directory under the platform user-data location. All shell traffic is admitted only for the exact runtime-selected loopback origin; private records/download requests also require the captured capability and reject cross-site or mismatched-Origin traffic. Launch-specific HTML is uncached and cannot be framed by another page. The download bridge has bounded concurrency and body deadlines, atomically publishes no-clobber files, and removes cancelled partials. The shell adopts Deno Desktop's startup window; native close synchronously fences gameplay ingress, starts a renderer-side autosave flush, and reads only that close request's JSON receipt. A verified receipt first cancels only non-authoritative downloads still receiving bodies, then allows HTTP admission to stop, active record commits to drain, and the process to exit; a missing or failed receipt keeps the window, server, and download ingress alive, with no heartbeat, watchdog, or timeout force-exit. The app config's desktop name, reverse-DNS identifier, and optional icon drive `deno desktop`; the default output is a host-platform preview, and explicit supported `--target <triple>` flags add cross-compiled packages per OS (macOS `.app`, Windows `.msi` installer, Linux `.AppImage`) with optional payload compression. Signing/notarization, per-platform launch smokes, and durable-store promotion are not yet live capabilities.

- Quick Save, automatic Save, and numbered manual Save slots (`manual.1`..`manual.N`) through a Host persistence facade; the manual slot count is Story-configurable (`manualSaveSlotCount` on the core application definition, engine default 8, range 0–99; zero disables numbered manual slots). The dev-server motion port (`/__sillymaker/dev-sources/motion`, dev only) reads documents with a sha256 content digest and writes by compare-and-swap: schema validation, motion-id stability, `*.motion.json` path restriction, temp-file + atomic rename, and deterministic formatting; conflicts report 409 and the Workbench offers a reload. `createDevServerMotionIoV1` is the browser client.
- Preview capture and preview cases (Motion Workbench M4): the inspect controller's `capture()` rebuilds the latest rendered frame as a detached settled `StageRenderTargetV1` (exiting ghosts dropped) plus the selected entry key — an editor-local fixture, never a Save, Snapshot, or replay anchor. The provenance card's "edit motion" hands that capture along, so the Workbench opens on exactly the scene the author clicked. `MotionWorkbenchLauncherV1` with `createMotionWorkbenchStoreV1` is the shared panel body: it prioritizes live capture over Story-declared named `MotionPreviewCaseV1` fixtures (reachable without replaying story progress) over the Story's fallback preview, and lists cases and motion sources in its empty state.

- Audio presentation: the Host-neutral `AudioHostV1` surface with a deterministic `createFakeAudioHostV1` for tests, and `createAudioPresenterV1`, which reconciles the Story's continuous audio intent per committed publication (idempotent replace/loop/fade, voice tied to say occurrences with stop/sustain and replay), plays each commit-only SFX at most once per presentation epoch through an instance-local consumed watermark, restores continuous intent across epoch changes without replaying history, and suspends/resumes with page visibility. `GameAudioV1` packages this lifetime as one component (host + presenter per mount, publication/effect subscriptions, page-visibility suspend, voice-replay registration) and subscribes to the player profile so the Settings volume/mute sliders drive the host live; the Engine Lab (silence-fallback degrade proof) and the Cat Cafe (real MP3 set: scene-driven BGM, resident rain ambient, one-shot cues mapped from existing transient effects) are its two consumers.
- VN player systems live behind the production Narrative definition: reveal-first Say activation, normal/auto/skip, Pause, Choice, presentation Barrier, History, and current-voice replay all route through the same occurrence-fenced interaction contract as manual input. Playback mode, reveal cursor, clocks, and timers are composition-owned transient state; they never persist or touch authoritative State. Story renderers receive only `NarrativeSurfacePlayerViewV1` and bounded callbacks, not a raw controller.
- Input routing, focusable code-native controls, settings, symbols, reduced-motion support, and content preferences.
- Keyboard and gamepad adapters: `installKeyboardAdapterV1` maps `KeyboardEvent.code` to semantic input actions through the Input Router's context priority (keys focused on editable or interactive elements never double as stage shortcuts, so accessible DOM controls keep native behavior), and `installGamepadAdapterV1` runs a minimal poll loop with rising-edge detection that stops on disconnect, teardown, or disposal. Pointer, touch, keyboard, gamepad, and Agents form the same semantic intents; physical input events never enter the CommandLog — only the gameplay semantic command a handler ultimately dispatches does. Player/presentation control actions (`playerInputActionIdsV1`: auto, skip, history, hide UI, voice replay) never masquerade as GameCommands, and the default GameRoot installs Story-configurable action maps for its lifetime while exposing the router through the slot context.
- Asset registry with requested-asset loading, fault diagnostics, and code-native fallback.
- Runtime art pipeline, end to end: a Story declares `assetSlots` + `assetPacks` in its presentation facet (validated into the resolved manifest with bytes/sha256/dimensions per provider); the manifest rides `createExtensions` to the UI, which builds `createAssetRegistryV1` over the injected image loader and resolves per-usage URLs inside Story renderers, falling back to code-native drawing per asset. The repository Vite config serves `<storyRoot>/assets/**` at its repository-relative runtimePath in dev and copies it into dist on build, so one runtimePath is true in dev, production Player, and the desktop shell. `deno task check:assets` verifies the real files against the declared digests. First real consumer: the cat-cafe 23-piece art pack.
- Title screen and settings baseline: an optional `BootSplashV1` front card (studio or game intro; auto-dismisses, any click skips) precedes `TitleScreenV1` (front door with New game / Continue / Load game / Settings, optional key art on an opaque canvas). Title layout lives in a CSS module (`data-title-screen` / `data-title-menu`) so a Story can restyle command placement and key art without fighting inline layout. Splash and Title are sequential scenes, not a translucent mask: while Splash or Title remains the desired WholeCanvas front door, DefaultGameRoot conceals gameplay layers (background, character, scene interaction, HUD, narrative) and hides the floating system menu; Title Settings/Load still open through the System host. Both are pure renderers inside the package-owned WholeCanvas authority; they no longer write Root/System lifecycle directly. With an application lifecycle, New game runs `lifecycle.restart()` and proceeds to the optional Story `titleScreen.beginNewGame(semantic)` only after an exact anchored result; a structured rejection/fault or thrown failure keeps the current title/foreground in place and never runs the opening hook. Without lifecycle, New game reports `unavailable` without invoking the hook, DevDock does not contribute Reinitialize, and programmatic `returnToTitle` remains shape-stable but asynchronously rejects with `ui.lifecycle_restart_unavailable`. In the standard composed Web path, anchored means Core replacement plus exact installed presentation-successor acknowledgment. The predecessor composition does not close System, call Overlay `closeAll`, or perform another cross-family reset, so a Surface opened by a successor subscriber remains current without a second publication delta. Openings that need an explicit boot command (not implied by the initial Snapshot) therefore stay on the title button instead of a second in-game control. Continue stays disabled until a runnable `auto.current` autosave exists. A Story may declare `customSaves` instead of the standard `saveLabels` / `saveGuard`; ambiguous dual configuration is rejected before mount. The title then replaces Continue with a Load launcher (`titleLoadGameLabel`) that opens the custom Saves component through the managed System session, preserving the same modal, input, focus, portal, and close authority. That Load control stays disabled until any slot is `valid` or `recovery_candidate` (not only `auto.current`); the composed Web path still lists slots through the maintenance save port so availability is known without mounting the default Save overlay. A successful load still dismisses the title through the anchored `load`/`import` epoch origin. `titleSettingsLabel` optionally replaces the title Settings control copy (in-game Settings keep `settingsLabel`). `DefaultSettingsSectionsV1` gives every application master volume/mute, text-speed and auto-wait preferences (persisted in the Host profile), a fullscreen toggle, and a developer-tools switch that persists the `debug_tools` + `cheats` capabilities together. A Story that actually consumes `skipCutscenes` can opt into its checkbox by supplying `settingsSkipCutscenesLabel`; other applications do not render an inert control. A Story that ships its own tooling surface can drop the developer-tools switch with `hideDeveloperToolsToggle: true` (the `?capability=debug_tools` URL opt-in keeps working). The DevDock and Story tuning panels open from Settings and stay out of the game UI by default.
- Custom-shell escape hatches: `hideSystemMenu` removes the default floating system menu for fully custom shells (SillyOS's desktop), and the slot context exposes `systemDialogs.openSettings/openSaves/returnToTitle` so Story UI (a Start menu, a pause menu, or an MV Return-to-Title ending) reaches the composition-owned System lifecycle without receiving raw close, Coordinator, epoch, instance, readiness, or topology authority. The open methods return structured preparing/applied/unchanged/rejected/faulted results; `returnToTitle` always returns a Promise, restarts and re-shows the title front door without flashing on New game when composed successor activation succeeds, and rejects asynchronously when lifecycle is unavailable. `resolvePreferredLocaleV1` (`@sillymaker/base`, pure and host-free) negotiates a Story's catalog locales against `navigator.languages`-style preference lists for automatic language selection.
- System menu discipline: the system layer hosts **one modal root at a time** through a composition-created opaque `SystemDialogSessionV1`; Settings and Saves replace each other in the same Coordinator slot, and the required `SystemDialogHostV1` never creates a fallback store. The standard Saves content lives in this layer — above the narrative panel, with the whole gameplay tree inert while open — and lists every slot in the port's enumeration order (current/previous autosave, quick, then the numbered manual slots) with saved-at timestamps; slot names for manual slots come from the `slotNames.manualSlot(index)` label formatter. Load, clear, and import confirmation is one exact-parent managed child of the current Saves root. `SystemDialogCustomSavesV1` supplies a React component identity that replaces only the Saves body while retaining the same launcher and lifecycle authority; the Host mounts it inside React instead of invoking a render callback. Successful load/import installs the presentation successor and makes every predecessor completion stale: the old confirmation/Saves continuation cannot close, finalize, or deliver a result into a fresh System root. The anchored `load`/`import` origin also dismisses the title screen, which is how Load game works from the front door. Stories may declare a save **safepoint** (`saveGuard` over the live publication): manual writes are disabled with the stated reason (for example mid-dialogue or mid-contest) while autosaves and loads stay available; authoritative snapshots are atomic either way, so the guard expresses game-design intent rather than data safety.
- Stage layer order is a published contract (`stageLayerIdsV1`): background, character, scene interaction, HUD, narrative, whole canvas, workspace overlay, system. Modal workspace overlays paint above WholeCanvas, and WholeCanvas paints above Narrative by construction. Paint order is token-driven end to end: the stage scale (`--silly-stage-z-*`) must match `stageLayerIdsV1` exactly and the within-layer surface scale must stay strictly increasing — both guarded by `stacking-tokens.test.ts`, and raw z-index numbers are forbidden in engine and Story code. Production Narrative and WholeCanvas Hosts own their layers' focus/inert/input isolation; Story renderers must not mount another shell or semantic writer. Dismiss paths that sync-unmount a surface on `pointerup` should arm `useStagePointerGestureFenceV1(context)` on that primary `pointerup` (not Escape) so the leftover browser `click` is swallowed on the `GameStage` root (`data-stage-root`) without entering Story state.
- Dismissal conventions: the backdrop click and the cancel action (right-click / Escape) dismiss the topmost dismissible window; a locked window (`dismissible: false`) consumes both without closing — only its explicit close control works, and the cancel never falls through to the window beneath. A stable WholeCanvas primary is not a generic dismissible window; only its package-owned exact-parent transient detail exposes the bounded Back/dismiss path. Stacking is safe by construction (lower layers inert, nested confirmations on their own stratum). Controls own their pointer buttons: right-click on any interactive element (including icon/text descendants) does nothing by default, may opt into an action via `data-secondary-action`, and the scene background routes the Story-configurable `cancel` (remappable, e.g. to rollback) through the pointer action map. Gameplay surfaces also disable text selection, image dragging, the iOS long-press callout, double-tap zoom, and scroll chaining wholesale. Native form controls (text fields, selects, textareas, checkboxes, ranges) take the theme automatically. Window exclusivity is structural — one system-dialog slot, one workspace primary (`openPrimary` replaces) plus a detail stack. A WindowManager (minimize/maximize/taskbar/z-order persistence) stays out of the engine. Letterboxed CSS-pixel floaters drag with `useClampedElementDragV1`; scaled MDI drag stays Story-side. Recipes live in design/window-model.md.
- Window chrome: `PanelV1` is the shared in-game window frame (visible title bar, optional header actions, close control, keyboard-focusable scrollable body). Close is a labelled button by default (`closeControl: "label"`) or an icon whose accessible name is `closeLabel` (`closeControl: "icon"`). `OverlayHostV1` wraps every workspace overlay in it, so gameplay windows (album, shop, inventory…) get consistent chrome for free, with content-first initial focus (the close button never steals it). Floating debug windows (`DevDockV1`) reuse the same chrome with the icon close and title-bar drag (`headerProps` + `useClampedElementDragV1`); they are not OverlayHost sessions. Styling comes exclusively from the published `--silly-*` theme tokens (colors, spacing, radii, control/target sizes, stacking). The default theme is professional-neutral dark (no brand hue) with compact control chrome: buttons and system bands size from `--silly-control-min-size` (2rem), while `--silly-target-min-size` (44px) remains the touch-target floor token for stage hit areas.
- Immutable presentation projection that combines semantic output with local presentation state without becoming gameplay authority.

- Stage hit regions: `StageContentResolutionV1.hitRegions` lets the content catalog resolve activatable regions per contentId + appearance (regions can move as a character grows); projection validates and bounds them (up to 64 regions per entry), and `SemanticStageHostV1` renders them as focusable transparent buttons only when the Story passes `onHitRegionActivate`, so pointer, touch, and keyboard reach the same semantic invocation path. Regions are presentation data and never carry gameplay authority; availability stays with semantic actions and module rules. The empty scene-interaction layer no longer mounts, so it cannot swallow stage pointer input.
- Stage entry opacity: `StagePlacementV1.opacityPermille` (integer 0–1000) is a required placement field — the authoritative settled opacity of each stage entry, entering Snapshots and Saves like every other placement channel (semantic stage contract revision 3). Transition fades and timeline overlay opacity compose multiplicatively on top as presentation and never persist.

## Web Host and application delivery

- Explicit Story-to-application composition and React mounting.
- Injectable autosave/checkpoint policy with a debounced browser default (`defaultWebAutosavePolicyV1`: quiet-period flush plus an every-N-commands checkpoint backstop), so committed Snapshots stay saveable at any time but long dialogues never write IndexedDB per line; the pagehide teardown flushes any pending capture before releasing the lease.
- Multi-instance lease coordination (`createWebInstanceLeaseCoordinatorV1`, composed automatically by the web start path): one unique lease owner per started tab/window/process, a declared `instancePolicy` applied against a live holder (`take_over` seizes at boot and reports `lost` when seized back; `read_only` never contends; `wait` runs read-only until the holder exits, then claims with CAS semantics so it never steals from a faster contender; `unrestricted` re-seizes on every loss — explicit last-writer-wins), a free lease always claimed regardless of policy, and an observable role port (`state.getCurrent`/`subscribe`, `refresh`, manual `takeOver`) handed to `application.ui()` and the started handle, together with `clearAllSaves` (Core wipe: drain pending Auto Save, then every slot) so a Story debug dock never loops `savePort.clear`. Role freshness combines a poll with a same-origin BroadcastChannel nudge on seizures; fencing tokens still reject every write from a seized instance, so no policy can corrupt a newer save.
- `createWebAudioHostV1`: the browser Audio Host — verifies fetched bytes against the declared length and sha256 before decode (mismatches degrade to silence with an integrity diagnostic), caches decoded buffers while letting failed loads open a new cycle on later demand, unlocks the AudioContext on the first user gesture (queued continuous channels apply on unlock; locked one-shots are dropped with a diagnostic, never replayed), applies permille gains with linear fades, and suspends/resumes/closes with page lifecycle. Autoplay denial and missing or undecodable media never block gameplay.
- Browser entropy, clock, logging, navigation, files, image loading, and IndexedDB adapters.
- Hash routing and query-driven development capabilities.
- Loader recovery when a Hotfix cannot be admitted.
- Vite development and static Player builds.

## Current non-goals and planned design areas

The engine does not currently provide a backend/account service, networked multiplayer authority, runtime LLM, ECS, SQL query layer, or a general-purpose database client for UI. These are descriptions of the present implementation, not permanent bans.

The Save migration product surface described above is implemented: supported
identities have checked-in canonical bytes, single-slot inspection and bounded
backup/recovery are player-accessible, and the maintained four-fixture corpus
runs through Story lifecycle and four-runtime parity gates. Opaque low-level
custom runtime controls and explicit legacy prepare-callback callers remain
outside the composite migration guarantee. PF5/M3 is complete; current/next work
is owned only by the [production-floor sequence](plans/2026-07-30-production-floor-sequence.md).

The script-language decision is durable: Story, Module, Narrative, UI, and official Hotfix code use TypeScript/JavaScript. SillyMaker does not plan Ren'Py DSL/Save compatibility, a custom script interpreter, or an untrusted-code security sandbox. Direct Host-global access remains possible JavaScript but is outside the supported engine API.

The Semantic Stage family (contracts, reducer, projection, transitions, reconciler, components), PendingInteraction, audio intent/presentation, the typed Timeline, the DevTools data plane (runtime inspector and Narrative graph), Cat Cafe's Story-local script-node Stage preview, Player rollback, the VN player systems, the capability-gated debug-command channel, and named-scenario `story simulate --trace` plus `story diff` tooling above are implemented. A generic arbitrary-snapshot preview, Timeline scrubber, audio/transition inspection, editors, the bounded Presentation Scene Graph, and advanced media/renderer adapters beyond the delivered audio intent stack remain planned in the [engine roadmap](roadmap.md); the retired V1 scene-graph stage system (StageSceneGraph, hit maps, spatial interaction surfaces, character rigs) was deleted with the first PoC rather than ported.

State access and persistence may be redesigned. The current exploratory direction is recorded in [the typed StateStore proposal](proposals/typed-state-store.md). Any adopted design should replace or simplify existing machinery rather than create two competing authoritative states.

The Engine Lab Story is a conformance rig, not a product design. Its module split, thresholds, and script exist to exercise engine contracts; new games should not copy them as gameplay guidance.
