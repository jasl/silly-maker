## Story authoring and resolution

- Typed `GamePackage`, `GameSimulation`, and `GameplayModule` definitions.
- A dedicated `@sillymaker/base/authoring` entry with `createRuntimeSchemaV1` (canonical-JSON output, deep-freeze, structured failures) and `fromStandardSchemaV1`, the official Zod adapter accepting any Standard Schema V1 implementation without leaking library types.
- `createGameAuthoringKitV1`: typed capability tokens, `requires`/`provides` with provider factories that build narrow read-only ports from the owner's State slice, a validated capability availability DAG plus an independent `initializesAfter` lifecycle DAG (stable diagnostic codes for missing/duplicate providers, cycles, and undeclared token access), stateful/stateless module helpers with derived proposal schemas, and composition into ordinary low-level module bindings. The low-level `defineGameplayModule`/`defineGameSimulation` API remains the escape hatch; one composition owns one resolved module graph.
- A composition-level transaction runner (`createTransactionRunner`) for cross-owner atomic commands: `read(token)` observes the command-start Snapshot, each owner accepts at most one proposal (duplicates fault with a stable diagnostic), and completed staged proposals apply in locale-independent UTF-16 code-unit module-ID order so declaration order or Host locale never changes apply/fact order, the candidate Snapshot, CommandLog, or replay. The engine owns slice replacement, schema/invariant validation, fact collection, commit/reject/fault envelopes, and RNG/sequence rollback. `commitAttemptV1`/`rejectAttemptV1`/`faultAttemptV1` are also public for hand-written executors.
- Engine-owned Strict Canonical Data admission at every public Session/Simulation/CommandLog command ingress and authoritative replay: one descriptor-safe command traversal rejects symbol-keyed members, extra own array properties, custom array prototypes, and represented accessors while generating the unchanged canonical bytes plus a new path-local ordinary-data projection. Only that projection is frozen and delivered to the executor/log/replay driver; admission neither retains nor freezes the upstream normalized identity (schema helpers may already have frozen their own output), shared aliases expand per canonical path, and ingress-attached Proxy/private/WeakMap state cannot cross the boundary. One exact-projection operation receipt prevents duplicate traversal. A malformed command fails before queue/status publication, RNG, Snapshot digest/freeze, continuity, or driver construction; Story schema/domain failures keep their existing result contracts, while canonical violations use root-exported `CanonicalJsonError` with stable `code` and JSON-Pointer `path`. Authoritative replay captures every source/command slot once, runtime-validates `game | debug`, prepares the projection vector, and freezes none until every entry passes; even a valid `null` projection is submitted without rereading its slot. Public `canonicalJsonBytes`, digest, Save, Debug Bundle, and valid CommandLog/replay bytes remain unchanged; best-effort inspection is unchanged. Direct generic CommandLog extras are conditionally projected/frozen as independent metadata while retaining public key order; enumerable collisions with engine-owned entry fields reject synchronously, and the standard Session path has no metadata traversal.
- Engine-owned finalized-evidence admission for Session, independent CommandLog, authoritative replay, Debug validation failures, and structurally attempt-shaped direct Simulation results: descriptor-only outer capture preserves getter-zero behavior and Standard Core's zero-RNG precedence; every evidence collection captures one own array `length` data descriptor and validates indices against that fixed length, so Proxy virtual length cannot alter the vector. Declared fact/rejection/debug-error schemas normalize each item before one Snapshot-free Strict Canonical Data projection traversal and freeze. The admitted projection flows into an engine-rebuilt attempt, and an exact admitted-attempt package-internal one-shot handoff carries it to CommandLog; admission itself neither retains nor freezes upstream normalized evidence, while a schema's own freeze contract remains in force and result/pre-attempt Snapshots deliberately retain authoritative identity. No public evidence hook, receipt, fault schema, result branch, or `GameSimulation` revision was added. Failure occurs before candidate Snapshot integrity/freeze/digest, log continuity, install, or publication. Session invokes its existing unexpected-fault normalizer once; only a valid same-Snapshot canonical fault fallback is logged and pauses the Session, while an invalid fallback rejects without recursive normalization or authoritative mutation. Opaque non-attempt `GameSimulationV1` generic results remain unchanged, and valid Snapshot/digest/Save/replay/DebugBundle bytes retain their existing formats.
- The bounded Strict JSON parser classifies number tokens from exact decimal coefficient/scale/exponent data before final conversion. Mathematical safe integers keep accepting alternate spellings such as `1.0`, `1e0`, and trailing-zero cancellation; rounded fractions reject as `number.not_integer`, true negative-zero spellings as `number.negative_zero`, and exact out-of-range integers (including non-finite conversion outcomes) as `number.unsafe_integer`. The enclosing byte limit is the resource bound, no Decimal/BigInt runtime or exponent-sized allocation is introduced, and decoder failure exposes no partial value. Valid Save metadata vectors, Save/DebugBundle normalization, canonical bytes, and digests remain unchanged.
- Standard Core treats Story-owned `createBootstrapInput` as a Host-ingress adapter. Before reading the RNG seed or invoking root/module initializers, one package-internal Strict Canonical Data traversal builds a path-local ordinary projection and one recursive freeze seals that engine-owned handoff. The adapter raw value remains caller-owned and unfrozen; shared aliases expand per path, cycles reject, and Proxy/private/WeakMap identity state cannot enter authoritative initialization. Construction, queued restart, and the captured extension `createInitialSnapshot` helper share the same stage order and failure precedence. The seed is descriptor-read and parsed once from the admitted projection, then the same frozen identity reaches the resolved root and each stateful module initializer in tuple order. Canonical, freeze, seed, Story/schema, and Snapshot failures retain their existing public channels and cannot install a partial Session, replay base, or persistence anchor. This adds no public bootstrap schema, receipt, or hook and preserves valid initial Snapshot, digest, Save, and replay bytes.
- A shared versioned `DiagnosticEnvelopeV1` (stable code, severity, phase, subject, JSON-pointer location, suggestion, Strict JSON details) used by authoring/definition/resolution failures, plus `collectGamePackageDiagnosticsV1` to aggregate a package's failures as structured diagnostics with human and JSON output.
- Separate simulation (`rule | value`) and presentation (`value | text | asset`) patch surfaces.
- Validated, frozen resolution with Story, engine, state-contract, simulation, presentation, asset, and patch-set identity.
- Story-local schemas, deterministic rule providers, command executors, queries, ViewModel projectors, scene graphs, catalogs, and renderer contributions.
- Optional lazily loaded Story tooling and tooling UI.

- The Base application composer (`@sillymaker/base/runtime`): `defineCoreGameApplicationV1` declares a Host-neutral core application (GamePackage entry, semantic adapter, validators, diagnostics extensions — no React, no Host handle); `resolveCoreGameApplicationV1` produces an immutable reusable resolved definition with structured failure reporting; `createCoreGameApplicationInstanceV1` creates a disposable instance that owns the Session, semantic port, persistence lease, diagnostics buffer, and lifecycle (`restart`). Failed construction and idempotent disposal leave no active owner or listener. Each instance maintains an instance-local presentation anchor/epoch that advances when the authoritative replay base is replaced (load/import/restart/debug anchor, with origin labels) and never enters SemanticPublication, semantic revisions, or Agent transcripts; `bindToCurrentEpoch` guards stale presentation callbacks structurally. `GameSession` keeps its current Snapshot digest as private derived evidence: committed Snapshots are frozen before one post-state digest, rejected/faulted attempts reuse the current digest, and every replay-base replacement refreshes Snapshot, CommandLog anchor, and digest together. The hot Session path retains object-identity and digest-chain checks without re-traversal, while the public low-level `createCommandLogV1` keeps full digest self-audit. Persistence can reuse that derived evidence only for the exact installed Snapshot under the exact Session runtime-control identity; custom/wrapped controls, cloned Snapshots, schema-normalized copies, and physical readback keep independent digest validation. The built-in Save repository also binds a successful exact write attempt to one private one-shot expected-byte receipt, so write verification can compare the physical readback without re-encoding the same current envelope; custom/decorated repositories retain the independent expected-encoding fallback, and lease, schema, digest, revision, and raw-byte readback checks remain in force. Built-in Save encoding performs canonical serialization and Strict depth/node/collection/string/dangerous-key checks in the same internal traversal; decoding untrusted bytes still uses the complete Strict parser before schema and digest validation. Autosave is an injectable policy (`every_commit` default, or `debounced` with `delayMs`, optional `checkpointEveryCommands`, an injectable scheduler for deterministic tests, and `flushAutoSave` for lifecycle hosts). Debounced admission requires `delayMs` to be a non-negative safe integer other than `-0`, and an optional checkpoint to be a positive safe integer; invalid policies fail before Session creation, persistence lease acquisition, timer access, or Host writes. A flush registers the exact current authoritative Snapshot at the Session queue front and succeeds only for that candidate's verified `auto.current` receipt. A same-sequence manual save cannot mask failure, initial and replacement Snapshots are eligible without a new command, duplicate exact captures reuse in-flight or already-verified identity, failed current attempts remain retryable, and replay-base replacement supersedes old-epoch receipts. Explicit slot saves remain available under any policy. Standard Core rejects a zero `xorshift32-v1` bootstrap/restored cursor before Story initial-state construction, command finalization, replay, or authoritative replacement; Save and DebugBundle codecs preserve `rng.invalid_state`, failed boot-resume keeps the fresh Session usable, and valid RNG/Snapshot/CommandLog/Save bytes remain unchanged. Low-level generic Session and replay constructors remain algorithm-agnostic escape hatches; no public admission hook was added. Low-level constructors (`createGameSessionV1`, `createPersistenceServiceV1`, `createSemanticGamePortV1`) stay public as escape hatches.
- `@sillymaker/base/testkit` ships `createGameHarnessV1`: a deterministic headless Game harness composed on the core application composer, so tests and real applications share one lifecycle contract. Stories supply only their semantic adapter (queries, projections, action catalog, previews, invocation mapping); the harness provides observe/preview/dispatch/waitForIdle, a deterministic trace, state digests, the persistence port, the underlying `application` instance, an admin surface (command log, authoritative replay, capability-gated debug control, explicit `inspectForTest`), and structured outcomes after disposal. The normal surface exposes no raw Snapshot or State setter. It also provides neutral generated 100/1k/10k/100k-entity Session workloads for repeatable Snapshot commit baselines, including a real two-owner `TransactionRunner` commit, a 256-command mixed transcript that exercises CommandLog eviction, authoritative replay of its retained 200 entries, and a fixed 100-entity two-commit `every_commit` persistence workload with `auto.previous` rotation. A separate package-internal memory baseline holds one neutral 1k-entity Session across 1,200 real cross-owner commits, crosses the 200-entry CommandLog retention boundary, and records process-isolated before/after-GC samples without exposing memory or instrumentation hooks to Story consumers; raw traversal, Save serialization, Strict JSON, memory, and GC instrumentation remain package-internal. A revisioned compact Save-metadata corpus now gives later runtime and Host parity tests one neutral expected-byte authority for summaries, player notes, capture-origin version stamps, unchanged unstamped records, and fresh fixed-clock export payloads; it does not expose production instrumentation or implement migration.
- The repository check includes a repository-internal, parser-backed authoritative determinism guard. Corrective C1 admits only runtime-bearing static ESM edges and exact one-argument ordinary-string-literal `import()`, while real CommonJS/createRequire routes fail with `dynamic_require`; C2 implements the conservative direct Date/`StaticString` safe-set, exact KnownDate terminals, constructor precedence, exact-singleton local provenance, and fail-closed cycle/budget handling. Runtime-bearing TypeScript internal `import =` aliases use the same concrete Date capture diagnostics and ranges as ordinary member capture; unknown `globalThis` and tracked-ambient descendants retain fail-closed provenance through sequence, pattern, alias, operation, and write shapes without overriding checked intrinsic or specific diagnostic winners. C3 removes Host `Date.parse` from Base timestamp admission: a package-internal integer parser owns strict persistence/diagnostic `IsoUtcInstant` values, while export filenames retain their separate loose legacy normalization. C4 removed the superseded broad Date evaluator/provenance paths, revalidated the 65-definition DET3b isolated-worker registry, and re-ran the fixed corpus and authoritative trace twice in Deno and twice in each of Chromium, Firefox, and WebKit; the aggregate corrective PF-DET gate is closed. These guards are deterministic-authoring checks, not a security sandbox, and do not expose raw Snapshot/RNG/CommandLog state.
- A Host-neutral `AgentGamePortV1` (`@sillymaker/base/runtime`): identity plus the player-safe SemanticGamePort operations with a bounded `waitForIdle` (timeout/AbortSignal return structured results without touching gameplay State). Save/import/export and read-only diagnostics are independent revocable capabilities (`createAgentPersistenceCapabilityV1`, `createAgentDiagnosticsCapabilityV1`); a revoked capability answers with `capability_revoked`. `createAgentTranscriptRecorderV1` records operation/result transcripts and `compareAgentTranscriptsV1` checks cross-host parity; the harness exposes `agent` plus capability grants for headless runs.
- `@sillymaker/tooling` (Node-only) hosts the versioned JSONL agent protocol: `createJsonlAgentHostV1` serves hello/observe/describeActions/preview/dispatch/waitForIdle over stdin/stdout-style streams (stdout carries protocol lines only; logs go to the injected sink), gates persistence/diagnostics methods behind explicitly granted capabilities, enforces line/depth/time limits with bounded structured errors and no stack leakage, and shuts down gracefully. `createJsonlAgentClientV1` is the matching minimal client. The method set is closed: no eval, no file paths, no DebugTools. Node in-process and JSONL runs of the same transcript produce identical semantic results and final digests.
- The UI composer (`@sillymaker/ui`): `GameViewportV1` maps a declared logical canvas (design resolution) onto the window with continuous fit scaling, themed letterbox/pillarbox, a `maxScale` center-stop, and read-only two-space conversion queries (`useGameViewportV1`); a `mode: "fluid"` variant fills the available area 1:1 instead (geometry reports the live size, scale 1, no letterbox) for shells that lay out like documents or desktops — SillyOS's phone-portrait desktop is the first consumer so renderers never build a second measurement authority. `createGameUiCompositionV1` composes the runtime presentation store (semantic projection plus the instance-local presentation anchor and Story UI state — never polluting SemanticPublication or Agent parity), input router, presentation intent router, Coordinator-backed Workspace Overlay session, and System dialog session with one disposal that revokes every subscription. `DefaultGameRootV1` is a complete playable shell with zero Story React code: viewport-managed seven-layer stage, designed default surfaces (Save overlay, Settings dialog, system menu), Story slots for stage/HUD/narrative/overlay contributions (adding one never modifies the composer), stage-space remount keyed by the presentation epoch, and a hard player/debug boundary — resident player DOM carries no debug vocabulary, machine probes are `data-*` only, and debug surfaces appear solely behind the `debug_tools` capability. DevDock remains the sole debug UI host: engine-owned and Story-owned typed contributions share its input, focus, portal, and `read_only` / `cheat` authority gates. The engine contributes a cheat-authority Session maintenance panel with mutually exclusive Export state, Import state, confirmed Clear all saves, and Reinitialize actions. Save cleanup runs behind the Core authoritative queue barrier: it cancels pending debounce work, drains already-issued autosaves, skips empty slots, checks every structured clear result, reports aggregated partial failures, and only reports completion when every non-empty slot was cleared; a later command may create a new autosave only after the cleanup barrier completes. Revoking the capability unmounts the panel and its transient state. That panel also reports the soft-failing human build stamp (application/engine package versions and full Git commits); an observed dirty checkout carries `-dirty`, while an unavailable cleanliness probe degrades that commit to `null`. Stories can read the same bounded optional value through `readVersionStampV1` / `formatVersionStampV1` without creating another debug host. Desktop packaging collects one immutable receipt for both Vite injection and artifact naming; filenames use only a bounded normalized version and shortened commit. The stamp remains diagnostic provenance and never becomes authoritative identity.
- The Web composer (`@sillymaker/web`): `startWebGameApplicationV1(application)` boots a complete browser application from one Story declaration (core definition + projector/catalog/slots/labels): web Host, the persisted capability session (Host records overlaid by the page request), core application instance (with Story extensions, live capabilities, and the application build digest), UI composition, default GameRoot mount, capability-gated browser automation bridge, optional pointer-adapter installation, optional native-behavior reset installation, lazy capability-gated DevDock contribution loading, DebugBundle UI-context binding, page-lifecycle teardown, and an idempotent `dispose` that unmounts, revokes listeners and automation generations, disposes Story UI resources, and releases the persistence lease. Story web entries contain no Session, Persistence, Diagnostics, Input, Automation, or HMR wiring: `installWebGameApplicationHmrV1` owns the dev accept boundary, fencing the predecessor, handing its persistence disposition to the successor (`rebootstrapDisposition`), and installing the next boundary. Web also owns a realm-stable, per-application Managed Surface epoch allocator: load/import presentation-anchor changes and HMR/rebootstrap successors cancel pending Overlay readiness and fence every predecessor receipt before successor ingress; the epoch is presentation/runtime identity and never enters a Save. The Engine Lab boots through this one declaration path; Story diagnostics services, DebugBundle codecs, and debug tooling are Story extensions the composer constructs, and diagnostics export lives in the DevDock — the resident player DOM carries no debug vocabulary.
- The engine browser suite (`deno task test:e2e:engine`) validates the engine against the Engine Lab Story in real browsers: default shell boot and play, save round-trips across reloads, DOM/Browser-Agent publication parity with player-safe results, capability gating and the player/debug boundary, WCAG A/AA sweeps, GameViewport letterbox geometry across declared viewports (including a 16:10 tablet and 200% zoom), reduced-motion, touch taps, and the Workspace Overlay open/replace/detail/close, locked dismissal, pointer/keyboard/focus, readiness/failure/cancellation, stale-receipt, and epoch-successor matrix — each declared Playwright project executes real cases, and every test enforces a pageerror/console diagnostic policy.
- The Engine Conformance route is the vertical acceptance: one short real path through two backgrounds, two characters, and a prop with all three transition kinds (background crossfade, character-entry slide, appearance cut), BGM/ambient/SFX/voice intent, typewriter, a choice whose precise branch atomically consumes a sample cross-module (narrative + samples + stage owners in one committed command), and the return to the ordinary SLG surface. The route completes through DOM clicks, the Node Agent port, the JSONL host, and the browser automation bridge; normal, reduced-motion, skip, and Browser-Agent runs export byte-identical authoritative simulation states; headless same-seed runs produce identical digests and command logs with authoritative replay passing; and mid-route save/load converges on the same end state. The Lab ships no media bytes, so every green run also proves the missing-image/missing-audio degrade paths.
- The AI-authoring canaries prove the authoring surface with real extension tasks implemented entirely on the Story side (zero engine `src` edits, verified by the package's public-import-boundary guard over every `.ts`/`.tsx` source): a currency/shop module (`lab.wallet` owns its slot; selling a sample and buying the stage banner each commit one atomic cross-module command with stable rejection codes and untouched digests on refusal), a relationship-conditioned narrative branch (a Story-side `branch` node kind routes the beta line on `rapport`, which is authoritative narrative State that enters Saves; a conformance test replays every branch chooser against its static successor annotations, and prediction collects both conditional lines without deciding), and a semantic React shop overlay (renders exclusively from the published projection with catalog-provided blocked reasons and dispatches ordinary semantic invocations). Deterministic acceptance lives in ordinary test code across headless, jsdom, and browser suites; model evals remain non-blocking trend instruments.
- `@sillymaker/tooling/project` owns the application project config: every application declares itself in its own `sillymaker.config.ts` (`defineSillymakerAppV1`, app-root-relative paths); `deriveStoryApplicationV1` anchors declarations for repository aggregation and `loadWorkspaceProjectV1` builds the workspace view from the root directory list. `runProjectCliV1` provides lifecycle verbs over declared applications: `inspect`, `check` (one or `--all`), `simulate` (with `--scenario` from the target's named scripts and `--seed` forwarded to the target factory), `dev --smoke` (boots the app's own Vite dev server and proves the served page), `build` (the application's own Vite config, output `<app>/dist-web`), `prebuilt-smoke` (file-level Player verification), and `desktop` where Desktop packaging is declared. `runSillymakerAppCliV1` runs the same surface app-locally (`story check .`). Application `package.json` files expose the relevant tasks (`build:web`, `preview`, `clean`, plus `build:desktop` where declared). `@sillymaker/tooling/vite` is the shared dev/build assembly (`createSillymakerAppViteConfigV1`: React, `/assets/**` runtime-asset serving/copying, share metadata, optional build-identity plugin, chunking policy). Dev-served runtime assets carry browser-correct content types for the common image/audio/video formats (including MV-style `.m4a`), and an application can extend or override the table through the factory's `runtimeAssetContentTypes` input without waiting for an engine release consumed identically by each app's `vite.config.ts` and the root `--mode` dispatch. Simulation runs exclusively through the player-safe Agent port, and process-level verbs run through an injectable runner so CLI contract tests cover the whole verb surface without spawning Vite.
- External application projects: private/local games (outside-checkout validation applications, personal experiments, and future external checkouts) are ordinary application projects that depend on the engine packages by relative `file:` path (`"nodeModulesDir": "manual"`), with their own `sillymaker.config.ts`, Vite config, tests, and app-local story CLI — no root registration, no engine `src/**` aliases. The former gitignored `project.config.local.ts` overlay is retired.

## Runtime

- `@sillymaker/base/story` is the Story authoring prelude: the current generation of every commonly authored contract re-exported under unversioned names (`SemanticStageState`, `StageMutation`, `PendingInteraction`, `NarrativeGraph`, `reduceStageMutations`, `evaluateInteractionResolution`, `defineCoreGameApplication`, …). It is a pure alias layer — a type-test matrix proves each alias identical to its versioned original — and it moves to a new generation together with the family it aliases. Versioned names remain the source of truth inside the engine; the superseded hand-assembly surfaces (`createGameRuntimeV1`, `createGameBootstrapControllerV1`/`Loader`, `createGameApplicationV1`, `useRuntimePresentationV1`) were removed once the composer path replaced their last consumer.

- One authoritative `GameSession` queue for gameplay dispatch and State replacement.
- Immutable, schema-validated `GameSnapshot` values; the session deep-freezes every installed Snapshot so live mutation attempts throw.
- Serializable purpose-labelled PRNG with rollback-safe command attempts.
- Structured commit, rejection, validation, and fault outcomes.
- Static module composition with explicit State ownership and dependency validation.
- Semantic preview/dispatch and immutable subscription publications for UI and automation.
- Lifecycle restart/rebootstrap and replay-base replacement.
- Semantic Stage contracts: versioned `SemanticStageStateV1` (ordered layers, stable `<layerId, tag>` entries, integer logical placement/appearance/camera targets) as plain canonical Save data, plus a pure atomic `reduceStageMutationsV1` batch reducer (`show`/`replace`/`hide`/`clearLayer`/`clearStage`/`setPlacement`/`setAppearance`/`setLayerTransform`/`setCamera`) that either commits a complete valid successor or rejects without touching the input state.
- Non-authoritative `StageRenderTargetV1` projection: a Story `StageContentCatalogV1` deterministically resolves semantic content into renderer IDs, asset IDs, accessible names, and Strict JSON props; unresolved content binds a code-native fallback renderer with structured diagnostics. The render target is rebuilt from State plus catalog and never enters a Save.
- Stage-driven projection wiring: Story game views may carry `SemanticStageStateV1` through the semantic publication (headless agents observe the semantic stage target), the Story UI projector rebuilds the render target every projection, and settled `requiredAssetIds` track the current target exactly — superseded assets leave the demand when the stage retargets.
- Stage transition contracts: plain, validated `StageTransitionDefinitionV1` data (cut/crossfade/slide, duration/easing, `block`/`target_active`/`skip_to_end` input policies, `settle_and_retarget`/`cancel_to_target` interruption, reduced-motion settle-or-fallback, immediate-or-bounded asset readiness, optional completion acknowledgment) plus a Story `StageTransitionCatalogV1` resolving old-to-new target changes. Definitions never enter the saveable stage state, and playing them never modifies gameplay State.
- `PendingInteractionV1`: the saveable interaction boundary (say, choice, pause, presentation barrier, and schema-registered custom surfaces) with three separated identities — author-stable `definitionId`, author-controlled `seenRevision`, and a per-entry-unique `occurrenceId` from a deterministic Story-owned sequence. `evaluateInteractionResolutionV1` is the single occurrence-fenced evaluator shared by the action catalog, preview, and queue-front dispatch; stale occurrences, wrong kinds, unknown or disabled choices, mismatched barrier transitions, and out-of-schema custom payloads reject without touching State. Renderer promises and callbacks never enter State or Saves.
- Typed audio media contracts: `AudioAssetSlotV1`/`AudioProviderEntryV1`/`resolveAudioManifestV1` keep music, ambient, SFX, and voice as their own contract (never images) with declared byte length and sha256 for response verification and a silence fallback. The saveable `AudioIntentV1` carries BGM/ambient channel targets (loop, permille gain, millisecond fades) and the current voice tied to its say interaction with a `stop_on_advance`/`sustain` policy; Saves reference stable asset IDs only.
- `AssetDemandPlanV1`: the explicit demand-plan contract (blocking/opportunistic priority, load group, concurrency budget, retry/backoff, retention) that loaders consume instead of accumulating one-shot requests; the budgeted plan scheduler integrates as media volumes grow.
- Typed Timeline contracts (R5): JSON-safe `TimelineDefinitionV1` (sequence/parallel/wait/tween/repeat/event over integer overlay channels — offsets, scale, opacity — targeting stage entries or the camera) with the `timelineV1` builder producing the identical contract as a hand-written literal. `parseTimelineDefinitionV1` rejects unknown kinds, invalid durations/easings, unbounded or over-deep repeats, and parallel branches writing the same channel; pure `evaluateTimelineAtV1`/`timelineDurationV1` make sampling deterministic and timer-free.

- Story meta progress: `PlayerProfileV1.meta` is a monotone `entryId -> value` map on the Host profile (the Seen registry generalized) with `markMeta` on the profile store; it survives every Game Save, restart, and rollback, and legacy profile records parse as empty. Stories own the key vocabulary (album unlocks, endings reached); the cat-cafe album overlay renders content-table entries against profile unlocks.
- Player rollback (R7): an opt-in `CoreRollbackPolicyV1` gives an application a bounded ring of committed Snapshots (default-pinned outcomes — RNG state travels inside every Snapshot, so a rolled-back retry reproduces the same result) with `classify` marking hard-barrier commands (settlements, irreversible beats) that clear every checkpoint behind them. `instance.rollback` exposes `available`/`toPrevious`/`subscribe`; a rollback replaces the authoritative Snapshot, advances the presentation epoch with origin `rollback` (stage, audio, and pending interactions re-project settled), reseeds on load/import/restart, and never touches Saves. Player history and rollback stay distinct from the CommandLog and Debug replay; the Seen registry lives in the Host profile and survives rollback by design. The Engine Lab and the Cat Cafe (contest entry and postgame confirmation as barriers, a HUD one-step-back control) are its two consumers.

- Commit-only transient effects: `CoreSemanticAdapterV1.projectTransientEffects` derives one-shot effect requests (for example SFX) from committed command facts, and the application instance emits them through `subscribeTransientEffects` stamped with a monotonic per-instance sequence and the presentation epoch at commit time. Effects never enter State, Saves, publications, or Agent transcripts, and load/bootstrap publications carry no history.
- `NarrativeHistoryV1`: the bounded player-readable backlog as Story/Narrative authoritative State — it enters Snapshots and Saves, restores to the exact occurrence, and is marked for M3 rollback to travel with the checkpoint Snapshot. It stays independent of the CommandLog (engine evidence), the Seen registry (Host profile), and Debug replay.
- Narrative graph lint and prediction: Stories project their typed TS narrative IR into the JSON-safe `NarrativeGraphV1` (no parser, no DSL — `createNarrativeGraphBuilderV1` and a hand-written literal produce the identical contract). `lintNarrativeGraphV1` reports duplicate nodes, missing entry/successors/call targets, unreachable nodes, pure loops with no interaction boundary, and duplicate interaction definitions as structured diagnostics with stable codes and source/pointer locations. `predictNarrativeDependenciesV1` walks every branch and call from the current cursor under an explicit node/depth/asset budget — it never executes a command, consumes RNG, or decides a hidden choice — and `narrativePredictionToDemandPlanV1` maps the collected text/asset/stage dependencies to an opportunistic prefetch `AssetDemandPlanV1`.
- Playback QoL consumers: `DialoguePanelV1` (`@sillymaker/ui`) is the assembled VN dialogue player — typewriter reveal (`createTextRevealV1`, profile text speed, reduced-motion instant), the auto/skip playback machine (`createPlaybackControllerV1`, dispatching through the shared resolution contract), Seen marking from the authoritative history into the Host profile, the history panel (`PanelV1` over the `NarrativeHistoryV1` backlog), the click-anywhere advance surface, and the quick menu (advance/auto/skip/history plus Story extras) in one component with neutral `data-dialogue-*` test selectors. The template, Bookshop, and Cat Cafe all mount it as a thin adapter (pending/history/profile/uiText/onResolve plus labels); the Engine Lab keeps its own player as the low-level rig. Speed/wait sliders ship in default Settings.
- `createPlayerProfileStoreV1`: the per-story player profile (Seen registry keyed by author-controlled `seenRevision`, plus text speed, auto wait, dialogue skip policy, `skipCutscenes`, and volume preferences) persisted in the Host `settings` record namespace — outside every Game Save, so loads never rewind reading progress or player playback choices, and corrupt records fall back to defaults. `skipCutscenes` is a Story-consumed preference for settling skippable presentation dwells; it must not bypass authoritative scheduler time or semantic commands, and older profiles soft-default it to `false`.

## Content database

- Story-defined static data tables: `defineContentTableV1` validates a table at definition (table-id pattern, per-row RuntimeSchema parsing — typically zod via `fromStandardSchemaV1` — unique non-empty string primary keys, row limits); `createContentDatabaseV1` validates cross-table references at construction and exposes typed read-only views: `byId` (KV), `findMany`/`findFirst` with `where` conditions (eq/ne/in, numeric comparisons, array membership) and ordering, plus `collectTextIds` for text-catalog joins. Numeric ordering compares relational sign without subtraction overflow; string ordering is fixed UTF-16 code-unit order and never consults Host locale. Content is authoring-time data: no runtime mutation, JSON-safe, deterministic, and part of Story identity through the ordinary source-digest path. Mutable game state stays in module state (atomic commits, Saves, rollback) — the static/dynamic boundary is the design's first principle. First real consumer: the cat-cafe example (activities, petting reactions, contest moves, rivals, album entries).

## Gameplay primitives

- Event pool: `parseEventConditionV1` validates restricted serializable condition trees (number/flag/label leaves, all/any/not composition, depth and branch bounds). Evaluation/draw captures each own enumerable numeric-context value once into an engine-owned projection, admits the complete projection as safe integers, and rejects fractional, non-finite, unsafe, or negative-zero values; inherited numeric properties are missing rather than an admission bypass. Draw also captures each candidate id/weight/condition once, then eligibility, accumulation, force, explanation, and selection consume only that projection. Eligible weights accumulate with a pre-add safe-integer overflow check across the complete authoring-order vector, including forced selection; invalid context/overflow fails before RNG or explanation. Valid draws use one purpose-tagged transactional-RNG roll with JSON-safe explanation data (considered, eligible weights, roll, winner), while debug force preserves eligibility and spends no draw. First consumer: the cat-cafe weekly regulars (conditions in content-table rows, draws inside the business transaction, explanations in facts).

## Persistence and compatibility

- Game-shell native-behavior reset (`@sillymaker/ui` `installNativeBehaviorResetV1`, declared per application via `nativeBehaviorReset` on the web UI definition): a "reset CSS" for browser input defaults — suppresses the context menu, text selection, touch callouts, and image drag document-wide so a Player feels like a game shell. Editable controls (`input`/`textarea`/`select`/contenteditable) keep native selection; interactive controls keep native menus and callouts; any subtree opts back in with `data-native-menu` / `data-native-text`. Document-scoped on purpose because Story overlays portal to `document.body`; disposal removes every installed piece. The reset is a presentation floor, not a semantic owner: its Window-bubble listener runs after the document-level pointer adapter, exposes no raw context-menu callback, and yields when that adapter has claimed the event. Remappable right-click stays with the Input Router (`data-secondary-action` on controls, stage `cancel` mapping), while `data-native-menu` is an absolute opt-out and the stage CSS keeps its own selection/zoom/scroll-chaining suppression for the shell subtree. The template enables it by default.
- Desktop-channel persistence preview: `createHttpHostRecordStoreV1` is the browser-side adapter for the trusted local records endpoint. The Deno save server and packaged shell validate same-origin JSON requests, bounded bodies, namespaces, revisions, paths, and stored records; their current JSON-file backend provides optimistic revisions, a serialized in-process queue, and atomic **per-record** replacement. It does not yet prove crash-atomic multi-record commits, cross-process CAS, or a portable collision-free filename mapping for arbitrary record keys, so it remains a preview/reference backend pending the [desktop durability plan](plans/2026-07-30-desktop-persistence-durability.md). `startWebGameApplicationV1` selects the HTTP adapter when the page runs with `?records=local` or the shell injects `__SILLYMAKER_RECORDS__`.
- Usable Desktop packaging preview: `deno task build:desktop` (where the application declares it; `deno task story desktop <app>` from the root) stages a thin shell shipped inside `@sillymaker/tooling`, serves the built Player from embedded `dist/`, injects the local-records signal plus one per-launch capability, and owns a save directory under the platform user-data location. All shell traffic is admitted only for the exact runtime-selected loopback origin; private records/download requests also require the captured capability and reject cross-site or mismatched-Origin traffic. Launch-specific HTML is uncached and cannot be framed by another page. The download bridge has bounded concurrency and body deadlines, atomically publishes no-clobber files, and removes cancelled partials. The shell adopts Deno Desktop's startup window; native close synchronously fences gameplay ingress, starts a renderer-side autosave flush, and reads only that close request's JSON receipt. A verified receipt first cancels only non-authoritative downloads still receiving bodies, then allows HTTP admission to stop, active record commits to drain, and the process to exit; a missing or failed receipt keeps the window, server, and download ingress alive, with no heartbeat, watchdog, or timeout force-exit. The app config's desktop name, reverse-DNS identifier, and optional icon drive `deno desktop`; the default output is a host-platform preview, and explicit supported `--target <triple>` flags add cross-compiled packages per OS (macOS `.app`, Windows `.msi` installer, Linux `.AppImage`) with optional payload compression. Signing/notarization, per-platform launch smokes, and durable-store promotion are not yet live capabilities.

- Quick Save, automatic Save, and numbered manual Save slots (`manual.1`..`manual.N`) through a Host persistence facade; the manual slot count is Story-configurable (`manualSaveSlotCount` on the core application definition, engine default 8, range 0–99; zero disables numbered manual slots). Multi-tab safety stays with the single-writer session lease — every slot write funnels through the one authoritative session. An explicit fresh Save to a Quick/manual slot may CAS-replace any Host-readable payload that current validation marks invalid (including an unsupported/future format); the old payload is not migrated or backed up, while load, stored export, and annotation remain fail-closed and Clear stays available as a separate recovery action. (Pre-release clean break: records stored under the retired bare `manual` slot key are no longer enumerated.)
- Save annotations: an optional `summarizeSave` hook on the core application definition captures application display lines whenever it creates a fresh record (auto, quick, manual, or current-state export); exporting an existing stored slot preserves that record's bytes. `annotateSave(slot, note)` on the player persistence port edits a bounded player note in place (empty string clears; snapshot, capture time, and summary stay untouched; auto slots stay read-only). `SaveSlotSummaryV1.annotation` exposes both to Story-owned/custom slot UI; limits live in `saveAnnotationLimitsV1` (8 lines × 120 code points, notes ≤ 64 code points). The built-in `SaveOverlayV1` does not yet render annotations. The record envelope treats `annotation` as additive-optional, so pre-annotation saves keep loading unchanged. A fresh capture may also carry an additive-optional diagnostic `versionStamp`: it identifies the build that captured the Snapshot, remains unchanged by note rewrites, autosave rotation, and stored-slot export, and is excluded from import compatibility and authoritative identity. The service normalizes the stamp once before lease acquisition; absent, malformed, throwing, or all-null sources are omitted so unstamped headless bytes remain unchanged.
- Canonical Save envelope encoding/decoding and staged strict import validation:
  bounded shell plus raw Snapshot digest, an explicit State-revision fence, then
  current Snapshot normalization plus a second digest before Story validation.
  A different revision is inspectable/exportable and maps to the distinct Player
  result `migration_unavailable` without rewriting the record or Session. This
  floor does not migrate or load historical revisions; there is no executable
  migration registry yet.
- Story, state-contract, engine, simulation, and patch-lineage compatibility information.
- Validated managed adoption for compatible simulation changes.
- Atomic record revisions, session lease/fencing, and HMR persistence handoff on conforming Host stores; browser IndexedDB is the production implementation, while the current desktop file backend is explicitly preview until its batch durability gate passes.
- Browser persistence through IndexedDB; injectable record stores for tests and other Hosts.
- File import/export through Host ports.

## UI and presentation

- React game shell with a central layered stage and runtime error recovery.
- HUD, narrative, workspace overlays, system dialogs, Save UI, and diagnostic export UI.
- Coordinator-backed Workspace Overlays: Stories declare each exact-ID target with `defineWorkspaceOverlayV1` (contract revision, dismissal policy, and required composition ports), provide concrete `overlayPorts` bindings when needed, and resolve its accessible name/content through `slots.overlayResolver`. `context.overlays` exposes only `openPrimary`, `pushDetail`, `closeTop`, `closeAll`, subscription, and an immutable primary/detail snapshot. Definition/schema/renderer/port/parent/slot failures return structured rejection before topology, input, or focus changes. Initial/detail preparation uses a code-native blocking fallback without mounting Story content; replacement retains the current DOM and focus until atomic readiness cutover, and failure or stale epoch receipts cannot replace it. The Coordinator is the only writable lifecycle authority: the compatibility `OverlaySessionStoreV1` delegates mutations directly to it and derives its immutable view from the same publication; the former independent writer and every asynchronous mirror are gone. This promotion covers Workspace Overlay only, not System dialogs, Narrative, or stable-target reconcile.
- `SemanticStageHostV1`: renders a projected Semantic Stage target with stable `layerId:tag` DOM identities, layer/camera/placement composition from integer logical units, Story-registered entry renderers, and a code-native fallback plus diagnostic for unregistered renderer IDs.
- Presentation runs and the Stage Reconciler: an injectable `PresentationClockV1` (animation-frame or deterministic manual), a reusable `PresentationRunV1` lifecycle (start/pause/resume/skip/settle/cancel/dispose with exactly-once outcome fencing; the future Timeline reuses it), and `createStageReconcilerV1`, which derives commit-only transition occurrences from committed target edges, renders previous + target + retained exiting entries, unions retained-exit asset demand, gates input by policy, suspends on page visibility, honors reduced motion live, drops stale edges across epoch changes (load/rollback), and emits exactly-once completion acknowledgments.
- `SemanticStageV1`: the animated stage component owning one reconciler per mount — feeds it committed publication targets, exposes `data-stage-settled`/input-gate lifecycle attributes for automation, and disposes every tick and listener on unmount, so browser tests observe lifecycle signals instead of sleeping.
- Timeline player and cue wiring: `createTimelinePlayerV1` executes timelines on the shared PresentationRun/Clock lifecycle (pause/resume/skip/cancel, playback-rate fast-forward, watermark-fenced exactly-once events, instant settle under reduced motion), and `SemanticStageV1` binds a Story timeline catalog to the composition cue registry — `presentation.play_cue` intents play decorative overlay cues (one active cue; a new cue cancels the previous) whose channels compose over the settled rendering and always clear on completion. Timelines never touch gameplay State or Saves.

- DevTools data plane (R6.1/6.2): `@sillymaker/ui/debug` ships generic read-only inspectors — `DebugValueInspectorV1` (live JSON over any observe/subscribe source, string-snapshot stable, size-bounded) and `DebugNarrativeGraphViewV1` (projected narrative graph with lint annotations and the pending interaction highlighted). The Engine Lab contributes four lazy DevDock panels (semantic stage, interaction + history, audio intent, narrative graph) behind the `debug_tools` capability; they read the exact publication surface players and agents consume and expose no setters.

- Audio presentation: the Host-neutral `AudioHostV1` surface with a deterministic `createFakeAudioHostV1` for tests, and `createAudioPresenterV1`, which reconciles the Story's continuous audio intent per committed publication (idempotent replace/loop/fade, voice tied to say occurrences with stop/sustain and replay), plays each commit-only SFX at most once per presentation epoch through an instance-local consumed watermark, restores continuous intent across epoch changes without replaying history, and suspends/resumes with page visibility. `GameAudioV1` packages this lifetime as one component (host + presenter per mount, publication/effect subscriptions, page-visibility suspend, voice-replay registration) and subscribes to the player profile so the Settings volume/mute sliders drive the host live; the Engine Lab (silence-fallback degrade proof) and the Cat Cafe (real MP3 set: scene-driven BGM, resident rain ambient, one-shot cues mapped from existing transient effects) are its two consumers.
- VN player systems: `createTextRevealV1` (clock-driven typewriter whose cursor is UI transient state, instant under reduced motion) and `createPlaybackControllerV1` — an explicit normal/auto/skip machine that dispatches through the exact same interaction-resolution contract as manual input, waits for full reveal plus the configured beat in auto, honors `skip_read`/`skip_all`, and stops at choices, pauses, barriers, custom surfaces, and unread lines. Playback mode and timers never persist and never touch authoritative State; hide-UI is pure presentation.
- Input routing, focusable code-native controls, settings, symbols, reduced-motion support, and content preferences.
- Keyboard and gamepad adapters: `installKeyboardAdapterV1` maps `KeyboardEvent.code` to semantic input actions through the Input Router's context priority (keys focused on editable or interactive elements never double as stage shortcuts, so accessible DOM controls keep native behavior), and `installGamepadAdapterV1` runs a minimal poll loop with rising-edge detection that stops on disconnect, teardown, or disposal. Pointer, touch, keyboard, gamepad, and Agents form the same semantic intents; physical input events never enter the CommandLog — only the gameplay semantic command a handler ultimately dispatches does. Player/presentation control actions (`playerInputActionIdsV1`: auto, skip, history, hide UI, voice replay) never masquerade as GameCommands, and the default GameRoot installs Story-configurable action maps for its lifetime while exposing the router through the slot context.
- Asset registry with requested-asset loading, fault diagnostics, and code-native fallback.
- Runtime art pipeline, end to end: a Story declares `assetSlots` + `assetPacks` in its presentation facet (validated into the resolved manifest with bytes/sha256/dimensions per provider); the manifest rides `createExtensions` to the UI, which builds `createAssetRegistryV1` over the injected image loader and resolves per-usage URLs inside Story renderers, falling back to code-native drawing per asset. The repository Vite config serves `<storyRoot>/assets/**` at its repository-relative runtimePath in dev and copies it into dist on build, so one runtimePath is true in dev, production Player, and the desktop shell. `deno task check:assets` verifies the real files against the declared digests. First real consumer: the cat-cafe 23-piece art pack.
- Title screen and settings baseline: an optional `BootSplashV1` front card (studio marks / AI-generation notices; auto-dismisses, any click skips) precedes `TitleScreenV1` (front door with New game / Continue / Load game / Settings, optional key art behind a darkening gradient), both rendering in the system layer until dismissed. New game runs `lifecycle.restart()` and proceeds to the optional Story `titleScreen.beginNewGame(semantic)` only after an `anchored` result; a structured rejection/fault or thrown failure keeps the current title/foreground in place and never runs the opening hook. Reinitialize follows the same result rule: an anchored restart closes the active System dialog and the complete primary/detail Overlay topology before showing the title, while a failure preserves that topology and foreground unchanged. Openings that need an explicit boot command (not implied by the initial Snapshot) therefore stay on the title button instead of a second in-game control. Continue stays disabled until a runnable `auto.current` autosave exists. A Story may declare `customSaves` instead of the standard `saveLabels` / `saveGuard`; ambiguous dual configuration is rejected before mount. The title then replaces Continue with an always-enabled Load launcher that opens the custom renderer through the existing System `saves` session, preserving the same modal, input, focus, portal, and close authority. A successful load still dismisses the title through the anchored `load`/`import` epoch origin. `DefaultSettingsSectionsV1` gives every application master volume/mute, text-speed and auto-wait preferences (persisted in the Host profile), a fullscreen toggle, and a developer-tools switch that persists the `debug_tools` + `cheats` capabilities together. A Story that actually consumes `skipCutscenes` can opt into its checkbox by supplying `settingsSkipCutscenesLabel`; other applications do not render an inert control. The DevDock and Story tuning panels open from Settings and stay out of the game UI by default.
- Custom-shell escape hatches: `hideSystemMenu` removes the default floating system menu for fully custom shells (SillyOS's desktop), the slot context exposes `systemDialogs.openSettings/openSaves/returnToTitle` so Story UI (a Start menu, a pause menu, or an MV Return-to-Title ending) opens the engine system dialogs programmatically (the dialog DOM portals independently of the caller's position) — `returnToTitle` restarts the session and re-shows the title front door without flashing on New game — and `resolvePreferredLocaleV1` (`@sillymaker/base`, pure and host-free) negotiates a Story's catalog locales against `navigator.languages`-style preference lists for automatic language selection.
- System menu discipline: the system layer hosts **one modal dialog at a time** (`SystemDialogSessionStoreV1` routes `settings` / `saves`; opening one replaces the other, Escape closes). The standard Save dialog lives in this layer — above the narrative panel, with the whole gameplay tree inert while open — and lists every slot in the port's enumeration order (current/previous autosave, quick, then the numbered manual slots) with saved-at timestamps; slot names for manual slots come from the `slotNames.manualSlot(index)` label formatter. `SystemDialogCustomSavesV1` may replace only that dialog body while retaining the same launcher and System lifecycle authority. A successful load or import closes the dialog and enters gameplay (the anchored `load`/`import` epoch origin also dismisses the title screen, which is how Load game works from the front door). Stories may declare a save **safepoint** (`saveGuard` over the live publication): manual writes are disabled with the stated reason (for example mid-dialogue or mid-contest) while autosaves and loads stay available; authoritative snapshots are atomic either way, so the guard expresses game-design intent rather than data safety.
- Stage layer order is a published contract (`stageLayerIdsV1`): background, character, scene interaction, HUD, narrative, workspace overlay, system — modal workspace overlays (album, journal…) paint above dialogue text by construction. Paint order is token-driven end to end: the stage scale (`--silly-stage-z-*`) must match `stageLayerIdsV1` exactly and the within-layer surface scale (`--silly-surface-z-*`: base < raised < front-door < splash < dialog-backdrop < dialog < confirm-backdrop < confirm) must stay strictly increasing — both guarded by `stacking-tokens.test.ts`, and raw z-index numbers are forbidden in engine and Story code. Custom narrative shells that do not mount `VnLayerV1` can still freeze stage pointer input with the public `useStageInputIsolationV1("narrative", active)` hook (same `inert` path the default VN layer uses). Dismiss paths that sync-unmount a surface on `pointerup` should arm `useStagePointerGestureFenceV1(context)` on that primary `pointerup` (not Escape) so the leftover browser `click` is swallowed on the `GameStage` root (`data-stage-root`) without entering Story state.
- Dismissal conventions: the backdrop click and the cancel action (right-click / Escape) dismiss the topmost window; a locked window (`dismissible: false`) consumes both without closing — only its explicit close control works, and the cancel never falls through to the window beneath. Stacking is safe by construction (lower layers inert, nested confirmations on their own stratum). Controls own their pointer buttons: right-click on any interactive element (including icon/text descendants) does nothing by default, may opt into an action via `data-secondary-action`, and the scene background routes the Story-configurable `cancel` (remappable, e.g. to rollback) through the pointer action map. Gameplay surfaces also disable text selection, image dragging, the iOS long-press callout, double-tap zoom, and scroll chaining wholesale. Native form controls (text fields, selects, textareas, checkboxes, ranges) take the theme automatically. Window exclusivity is structural — one system-dialog slot, one workspace primary (`openPrimary` replaces) plus a detail stack — and the free-window tier (drag/minimize/maximize) deliberately stays out of the engine with game-side recipes documented in design/window-model.md.
- Window chrome: `PanelV1` is the shared in-game window frame (visible title bar, optional header actions, close control, keyboard-focusable scrollable body) — the `OverlayHostV1` wraps every workspace overlay in it, so gameplay windows (album, shop, inventory…) get consistent chrome for free, with content-first initial focus (the close button never steals it). Styling comes exclusively from the published `--silly-*` theme tokens (colors, spacing, radii, target sizes, stacking).
- Immutable presentation projection that combines semantic output with local presentation state without becoming gameplay authority.

- Stage hit regions: `StageContentResolutionV1.hitRegions` lets the content catalog resolve activatable regions per contentId + appearance (regions can move as a character grows); projection validates and bounds them (up to 64 regions per entry), and `SemanticStageHostV1` renders them as focusable transparent buttons only when the Story passes `onHitRegionActivate`, so pointer, touch, and keyboard reach the same semantic invocation path. Regions are presentation data and never carry gameplay authority; availability stays with semantic actions and module rules. The empty scene-interaction layer no longer mounts, so it cannot swallow stage pointer input.
- Stage entry opacity: `StagePlacementV1.opacityPermille` (integer 0–1000) is a required placement field — the authoritative settled opacity of each stage entry, entering Snapshots and Saves like every other placement channel (semantic stage contract revision 3). Transition fades and timeline overlay opacity compose multiplicatively on top as presentation and never persist.

## Current non-goals and planned design areas

The engine does not currently provide a backend/account service, networked multiplayer authority, runtime LLM, ECS, SQL query layer, or a general-purpose database client for UI. These are descriptions of the present implementation, not permanent bans.

The script-language decision is durable: Story, Module, Narrative, UI, and official Hotfix code use TypeScript/JavaScript. SillyMaker does not plan Ren'Py DSL/Save compatibility, a custom script interpreter, or an untrusted-code security sandbox. Direct Host-global access remains possible JavaScript but is outside the supported engine API.

The Semantic Stage family (contracts, reducer, projection, transitions, reconciler, components), PendingInteraction, audio intent/presentation, the typed Timeline, the DevTools data plane (runtime inspector and Narrative graph), Player rollback, the VN player systems, the capability-gated debug-command channel, and named-scenario `story simulate --trace` plus `story diff` tooling above are implemented. The bounded Presentation Scene Graph, the remaining DevTools steps (arbitrary-boundary Stage preview, Timeline scrubber and audio/transition inspection, editors), and advanced media/renderer adapters beyond the delivered audio intent stack remain planned in the [engine roadmap](roadmap.md); the retired V1 scene-graph stage system (StageSceneGraph, hit maps, spatial interaction surfaces, character rigs) was deleted with the first PoC rather than ported.

State access and persistence may be redesigned. The current exploratory direction is recorded in [the typed StateStore proposal](proposals/typed-state-store.md). Any adopted design should replace or simplify existing machinery rather than create two competing authoritative states.

The Engine Lab Story is a conformance rig, not a product design. Its module split, thresholds, and script exist to exercise engine contracts; new games should not copy them as gameplay guidance.
