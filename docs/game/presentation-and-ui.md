# Project Tavern presentation and UI redesign

状态：2026-07-20 接受的活动产品设计；实现随 vNext C3/D/E2 分片推进（见 §8）。本文定义 Tavern 的画面框架、视觉语言和"能玩"验收；具体玩法动词与数值由玩法重设计（见 [gameplay redesign status](README.md)）决定后绑定。

绘制与外壳的引擎标准见 [Game viewport and UI shell design](../engine/design/game-viewport-and-ui-shell.md)；本文只提供 Tavern 的具体值与画面设计。

## 1. Relationship to the first visual track

首个 PoC 期间已经形成过一版视觉方向（归档于 [first web visual pack](../archive/2026-07-first-poc-goal/art/first-web-visual-pack.md)），包含视觉语言、逻辑画布、遮挡分区、女主锚点与七张整屏概念稿计划，并实际生成过四张候选稿。该轨道设计了"人工批准后晋升为运行时素材"的闸门，但晋升从未执行，工程 Goal 全程运行在 code-native fallback 上——这是当前界面没有任何视觉的直接原因。

本文把其中仍然有效的决定显式搬进活动文档（画布、分区、色板、角色锚点、素材边界），归档文件此后只是历史证据。已找回的四张候选稿位于本地忽略目录 `art-source/aigc/candidates/recovered-first-web-pack/`，作为风格锚点参考；是否直接采用由所有者在素材晋升时决定。

## 2. Reference usage boundary

所有者提供的商业游戏界面截图只由人观察，用于归纳布局、信息密度与交互范式。它们不进入仓库、生成输入、测试或素材管线；本文吸收的是抽象 UI 范式（顶部资源带、行动卡、任务清单、卡片式工作台），不复刻任何具体作品的构图、角色或美术。

## 3. Visual language

沿用并确认 v2 方向：克制的日式低魔幻想插画。场景材质偏写实（木材、灰泥、粗布、旧铜，保留磨损与自然纹理），人物保持清晰动画式轮廓与克制赛璐珞明暗；日间清冷天光配暖木色，夜晚灯火与窗外蓝调形成冷暖对比；小镇有战后重建痕迹但氛围温暖，不做糖果色童话或压抑黑暗奇幻。

Story 主题 token 基准值（对接引擎 token 合同）：

| 角色            | 基准色    | 用途                   |
| --------------- | --------- | ---------------------- |
| `ink-950`       | `#171B26` | 舞台遮罩、深色面板     |
| `ink-800`       | `#283043` | 面板与顶部 HUD         |
| `parchment-100` | `#EEE5D2` | 主文字与浅色详情面     |
| `brass-500`     | `#C69A57` | 边框、选中态、重要资源 |
| `amber-500`     | `#D8863B` | 行动与暖光强调         |
| `sage-500`      | `#66877A` | 正向、恢复与生活设施   |
| `danger-500`    | `#B95E55` | 风险、拒绝与危机       |

面板基调是墨蓝半透明底、羊皮纸文字面、黄铜描边；界面动画 160–240 ms，尊重 `prefers-reduced-motion`。女主角色锚点（19 岁、栗棕及肩发低侧辫、灰绿眼睛、日常工作服、生活化姿态）沿用归档设定，除非玩法重设计明确推翻。

## 4. Canvas and zones

- 逻辑画布 `1600×1000`（16:10），背景母版 `2560×1600`；4:3 核心安全区 `x=133..1467`；
- 顶部 HUD 带：`y=0..96`；
- VN 对话带：`y=720..1000`；
- 轻量行动/互动入口：`x=1240..1560, y=120..700`；
- Workspace Overlay 区：`x=220..1380, y=110..920`；
- 女主默认脚底 pivot `(1060, 930)`，主体保持在 4:3 安全区内；
- 门、柜台、壁炉、摊位、地图节点等可交互物不得只存在于 16:10 两侧裁切区；
- 1024×768 整舞台缩放；竖屏使用显式重排 variant；超宽居中 letterbox。

这些值由 Tavern application 通过引擎 GameViewport 声明；美术、Stage placement 与 HitMap 全部使用逻辑坐标。

## 5. Screen inventory

### 5.1 主舞台（常驻画面）

场景优先：完整酒馆/市集/地图场景占满画布，女主以当前活动姿态存在于场景中（擦桌、记账、读信），可附气泡短语与好感标记。常驻 UI 按 shell space 锚定：

- **左上时间胶囊**：星期/日次 + 时段（含昼夜图标），紧邻"跳过/推进时段"入口；
- **顶部资源带**：行动点、体力/心情、现金、声望、税/债务等紧凑资源 chip 横向排列，图标用 `GameSymbol`，数字代码渲染；
- **行动入口卡**：主要经营动词（如采购、营业、拜访、地图、仓库——最终集合随玩法重设计确定）以插画卡片呈现，主次分级（大卡 + 小卡）；
- **任务/待办追踪器**：左下可折叠面板，按人物/线索分页，显示已完成与进行中的条目；
- **右缘工具栏**：低频功能（日志、图鉴、设施等）竖排小按钮，可带提醒角标。

### 5.2 Workspace Overlay 族

采购、库存、设施、账本、人物资料等大型工作台覆盖舞台中央（舞台边缘仍隐约可见），统一框架：

- 顶部品类 tab 栏；
- 可选的流程/时间线指示（如送货进度点）；
- 内容主体为卡片网格：物品插画 + 品质/数量标记 + 状态槽，卡片为羊皮纸底黄铜描边；
- 底部确认栏（主行动 + 次行动），危险操作用 `danger` token；
- 打开/关闭有短转场，Esc/关闭按钮/遮罩点击可退出，焦点受困于面板内。

### 5.3 VN 对话层

底部对话框：人名牌 + 正文 typewriter + 继续指示；上缘控件提供 history、auto、skip、hide UI 与语音重播（对接引擎 R4 player systems）；choice 以居中阻塞层呈现。VN 层激活时行动入口与资源带按策略淡出或保留。

### 5.4 全景画面

世界地图与市集作为完整场景舞台，交互节点是场景内可点击对象（走 HitMap/scene interaction），不是列表菜单。具体节点集合随玩法重设计确定。

### 5.5 系统 surfaces

标题/继续画面、Save/Load、Settings、周结算等使用同一 token 体系与对话框框架；诊断导出只出现在 Settings 的支持区或 DevDock，遵守引擎 player/debug 边界。

## 6. Asset plan

- 重启"锚点 → 整屏概念稿 → 人工批准 → 晋升"流程；归档视觉包 §6 的一锚点 + 七屏清单仍是有效起点；
- 晋升继续走既有政策：人工复制进运行时素材目录、登记 manifest、摘要/尺寸校验；**本轮必须实际执行晋升**——这是上次断裂的环节；
- UI chrome（面板框、卡片框、按钮底）作为类型化 `ui` 素材进入 manifest，缺失时 code-native 面板兜底；
- HUD 数字、文本、进度条、系统图标继续由代码渲染，不从概念稿切图；
- AIGC 源图保持 archive-only，不进入 git 与 Web Artifact。

## 7. "能玩" acceptance bar

Tavern presentation rebuild 完成的最低标准：

1. 一条完整游戏循环——开始周期、选择方针、采购、营业推进、触发一段 VN 事件、存档并读档、看到周期结算——全程只使用本文设计的界面；
2. 黄金路径上零斜纹占位、零裸语义容器；缺失素材只允许出现"朴素但成立"的 code-native 面板；
3. 常驻文本全部可读（对比度与字号阶达标），焦点可见，命中区 ≥ 44×44 CSS px；
4. `1600×1000`、`1024×768`、平板横屏与 200% zoom 下核心画面可用，letterbox 正确；
5. 玩家 UI 零 debug 词汇；`?capability=debug_tools` 时 DevDock 完整出现；
6. normal 与 reduced-motion 路线得到相同 authoritative 结果；
7. 以上各条有对应的 PoC/产品 E2E 断言，不依赖人工逐次确认。

## 8. Execution slot

重绘不等待引擎全部完工，按依赖分片跟进 vNext 各阶段，每片都让 Tavern 作为真实第二消费者紧跟引擎验收：

- **美术轨道立即启动（零引擎依赖）**：锚点 → 整屏概念稿 → 人工批准 → 素材晋升；本轮必须实际执行晋升；
- **C3 落地后：外壳重绘（第一个"能玩"检查点）**：viewport、token、HUD/资源带、Overlay 框架、Save/Settings/系统对话框与 debug 边界修复；旧静态场景渲染暂垫在新外壳之下；
- **Phase D 落地后：舞台重绘**：语义舞台、人物进退场、转场接入真实画面；
- **E2 落地后：VN 层重绘**：对话框、typewriter、history/auto/skip 控件；
- **F3 保持薄迁移**，只负责删除被替换的旧 UI 路径与通用胶水；
- C3 之前不修补现有 PoC UI——它建立在将被替换的 V1 合同上；
- 画面框架可以先行实现为可玩壳（用现有 PoC 动词占位），具体动词与内容随 core-loop 设计确定后替换。
